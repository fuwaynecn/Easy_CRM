## 1. 本机环境速查

| 组件 | 值 | 本机特有的坑 |
|---|---|---|
| PostgreSQL | 便携版在 `.tmp\pg`，端口 **55432**，trust 认证 | 机器重启后必须重跑一次启动脚本；本机没有 Docker，不要用 `docker compose` |
| 开发库 | `easycrm`（种子数据） | `easycrm_test` 由 pytest 自建，验收不要动它 |
| 后端 | `127.0.0.1:8080` | **8000 端口被系统禁用，绑定会报 WinError 10013**，一律用 8080 |
| 前端 | `localhost:5173`（Vite） | 代理目标默认仍是 8000，本机必须用 `VITE_API_PROXY` 覆盖成 8080 |

## 2. 启动（按顺序，全部在 PowerShell 里）

### 2.1 启动数据库

```powershell
cd E:\Wayne\Doc\CY_CRM
powershell -ExecutionPolicy Bypass -File .tmp\pg\start-pg.ps1
```

预期最后一行：`就绪：PostgreSQL 16.x，端口 55432，数据库 easycrm / easycrm_test`。

- 脚本幂等：已在跑时不会重复启动；机器重启后必须再执行一次。
- 不要手工 `pg_ctl stop` / 杀进程：其它会话和 pytest 都在用这个实例。

### 2.2 灌种子数据

```powershell
cd E:\Wayne\Doc\CY_CRM\backend
.venv\Scripts\python -m scripts.seed
```

预期：打印各表"本次新建 N 条"，末尾列出 5 个种子账号。

- 幂等：重复执行不报错、不产生重复数据（按部门名 / 登录名 / 客户全称 / 联系人姓名判重）。
- 环境守卫：`ENVIRONMENT` 不是 `dev` / `test` 时**拒绝执行**并退出码 1（见 §4.3）。本地默认 `dev`，不用管。

### 2.3 启动后端

```powershell
cd E:\Wayne\Doc\CY_CRM\backend
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

验证：浏览器打开 <http://127.0.0.1:8080/health>，应返回 `{"status":"ok"}`。

- 若报 `WinError 10013`：端口被系统占用/禁用。**不要换回 8000**，换 8081 并同步改 §2.4 的代理目标。
- 启动日志出现"JWT 密钥仍是开发占位值"的中文告警是**预期**的（本地），见 §4.1。

### 2.4 启动前端

```powershell
cd E:\Wayne\Doc\CY_CRM\frontend
$env:VITE_API_PROXY="http://127.0.0.1:8080"
npm.cmd run dev
```

打开 <http://localhost:5173>，应落到登录页。

- 代理目标只在 dev server 启动时读一次：改了 `VITE_API_PROXY` 必须重启 dev server。
- 前端调接口是相对路径 `/api/...`，由 Vite 代理转给后端；直接访问 5173 的页面前端与后端都要在跑。

## 5. 部署前必改的 4 项

任何一项没做，都不算可以上线。

### 5.1 `JWT_SECRET`：换成 ≥32 字节随机值

- 现状：`backend/app/core/config.py` 里是开发占位值，`create_app()` 启动时会打中文告警
  「当前 JWT 密钥仍是开发占位值，请通过环境变量 JWT_SECRET 配置真实密钥」。
- 做法：生成一次，写进部署环境的 `.env`（不要提交仓库）：
  ```powershell
  cd E:\Wayne\Doc\CY_CRM\backend
  .venv\Scripts\python -c "import secrets; print(secrets.token_urlsafe(48))"
  ```
- 验收：重启后端，**告警消失**。占位值上生产等于所有 token 可被伪造。

### 5.2 `COOKIE_SECURE=true`

- 现状：默认 `false`，refresh cookie 没有 `Secure` 属性，会以明文 HTTP 传输。
- 做法：部署环境设 `COOKIE_SECURE=true`（并且前端必须走 HTTPS）。
- 验收：登录后 DevTools → Application → Cookies → `refresh_token` 的 `Secure` 列打勾；
  或看登录响应头 `Set-Cookie` 里含 `Secure; HttpOnly; SameSite=Lax`。

### 5.3 `ENVIRONMENT=production`

- 现状：默认 `dev`。这个值只影响两件事，但两件都是安全相关的：
  1. 种子脚本的环境守卫（`scripts/seed.py` 只允许 `dev` / `test`，其余拒绝执行）——
     写成 `dev` 就等于给生产留了"跑一下 seed 就有 5 个口令已知账号"的入口；
  2. `COOKIE_SECURE` 未开启时的启动告警（非 dev/test 才触发）。
- 做法：部署环境设 `ENVIRONMENT=production`。
- 验收：`ENVIRONMENT=production` 时执行 `python -m scripts.seed`，应打印「拒绝执行种子脚本…」并退出码 1。

### 5.4 反向代理层加登录限流

- 现状：应用层只做了**按账号**的失败锁定（连续 5 次失败锁 15 分钟，计数落库），
  **没有**按 IP / 全局限流。攻击者轮换账号名做撞库，应用层拦不住。
- 做法：在 nginx（或所用网关）对 `POST /api/v1/auth/login` 加 `limit_req`：
  ```nginx
  limit_req_zone $binary_remote_addr zone=login:10m rate=20r/m;

  location = /api/v1/auth/login {
      limit_req zone=login burst=10 nodelay;
      limit_req_status 429;
      proxy_pass http://127.0.0.1:8080;
  }
  ```
- 注意：办公楼常见单一 NAT 出口，全公司共用一个 IP。按 IP 限太严会误伤正常登录，
  建议 20 次/分钟 + `burst`，并对 429 给出中文提示。
- 验收：连续快速登录 30 次，第 N 次起返回 429。

### 5.5 顺手确认（不在这 4 项里，但漏了会出事）

- `CORS_ORIGINS` 指向真实前端源（默认 `http://localhost:5173`，生产必须改）。
- 后端不要用 `--reload`；多 worker 时也无需额外配置（登录失败计数落库，不靠进程内缓存）。
