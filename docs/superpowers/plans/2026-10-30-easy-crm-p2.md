# Easy CRM P2 实施计划（销售机会 · 看板 · 阶段历史）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让销售能录入销售机会、在列表与看板里推进阶段，并把每一次阶段变更落成不可绕过、可供报表使用的历史记录。

**Architecture:** 沿用 P1 的模块化单体：新增 `app/modules/lost_reasons/` 与 `app/modules/opportunities/`，每个包含 `models/schemas/service/router`。机会的可见性与可写性**完全继承客户**——读取从 `app/db/scope.py` 的 `customer_query(actor)` 起步，写入先过 `get_customer` + `assert_customer_writable`，机会模块不另建一套作用域规则。阶段变更只走 `POST /opportunities/{id}/stage`，由 service 层在同一事务里写 `stage_histories`，`PATCH` 不接受 `stage`，路由层无法绕开历史记录。

**Tech Stack:** 沿用 P1，不新增依赖。后端 Python 3.12 / FastAPI / SQLAlchemy 2.0（同步）/ Alembic / Pydantic v2 / PostgreSQL 16；前端 React 18 + TypeScript + Vite 5 + Tailwind 3.4 + TanStack Query 5。看板拖拽用原生 HTML5 drag 事件，**不引入 dnd-kit 之类的依赖**。

**Spec:** `docs/superpowers/specs/2026-10-29-easy-crm-design.md`（§3.5–§3.7、§3.10、§5、§6.2–§6.3）

## Global Constraints

P1 的 Global Constraints **全部继续有效**，逐条列在这里，执行时不得违反：

- 数据库与接口时间一律 UTC（`timestamptz` / ISO 8601 带偏移）；"今天""逾期"等业务判断用 `Asia/Shanghai` 换算后判断。
- 金额 `numeric(14,2)`，币种 CNY。**接口线上形式是字符串**（`"1234.50"`），已实测：Pydantic v2 + FastAPI 对 `Decimal` 序列化成定点字符串，前端按字符串处理、展示时格式化，不做 `Number()` 再 `toFixed()` 的往返（`0.1+0.2` 那类误差就这么进来的）。
- **所有客户相关读取必须从 `app/db/scope.py` 的 `customer_query(actor)` 起步**；机会的可见性用 `Opportunity.customer_id.in_(customer_query(actor).with_only_columns(Customer.id))` 表达，禁止自己拼可见性条件。
- **写前必过 `assert_customer_writable(customer, actor)`**（公海客户对 sales/manager 只读）。
- 越权一律 403；不存在 404；取值非法 400；与现有数据冲突 409；错误体统一 `{code, message, detail}`。
- 软删用 `deleted_at`，所有列表/详情过滤 `deleted_at IS NULL`。
- 命名：Python snake_case；前端本地标识符 camelCase，但**镜像后端 wire 字段的 DTO 保持 snake_case**（`frontend/src/api/types.ts`）。
- 数据库约束必须显式命名（`CheckConstraint(name=...)`、索引显式 `name=`）；命名约定在 `app/db/base.py`。
- 测试跑真实 PostgreSQL（`easycrm_test`），禁止 SQLite；**不许只断言状态码**（要断言 `code` 字段）；不许造假用户/假场景去测未实现的功能。
- 前端无自动化测试框架（spec §12 已定）：前端任务的"红/绿"由 `tsc --noEmit` 与 `vite build` 承担，外加手测清单。
- 每次阶段变更必须由 service 层写一条 `stage_histories`；`PATCH /opportunities/{id}` 不接受 `stage`。
- 后端测试必须先红后绿：先跑一次失败，把**原始输出**贴进报告，再实现。

## P2 裁定（本计划与 spec 的实现级决定，执行时不要再讨论）

分支与范围：

1. **分支**：P1 已 fast-forward 合并进 `main`（`6f183db`），P2 在 `feat/p2-deals` 上做。
2. **一个客户可以有多个机会**（先买设备、后买耗材）。不加唯一约束。
3. **输单原因预置 7 条**，取自 spec §3.10「初始数据」原文：价格过高、交期不满足、技术方案不匹配、客户预算取消、客户选择了竞品、项目延期搁置、其他。
4. **字典管理 CRUD（POST/PATCH/DELETE `/admin/lost-reasons`）与 `/admin/lost-reasons` 页面不在 P2 范围**：P2 的 UI 里没有它们的消费者（管理员后台属 P5/P6），spec §3.10 的"管理员可增删改"改由 P5 后台一并交付。P2 只交付表、种子与只读接口 `GET /lost-reasons`。**代价**：P2 上线后想加一条输单原因只能跑 SQL 或重跑种子；记进交接文档的已知债务。

机会字段与规则：

5. **机会负责人 = 客户负责人**：`owner_id` 在创建时直接从 `customer.owner_id` 取，请求体不接受 `owner_id`（`extra="forbid"` 会 422）。
6. **公海客户不能建机会**（机会 `owner_id` 是 NOT NULL，而公海客户没有负责人）→ 400 `invalid_value`「客户未分配负责人，请先领取或分配后再新建机会」。管理员也不豁免：机会负责人必须与客户一致，给公海客户机会就得先给客户一个负责人。
7. **创建时阶段只能是四个推进阶段**（`contact/needs/proposal/negotiation`），传 `won`/`lost` 是 400。理由：`won` 要 `won_at`、`lost` 要原因，这两个字段只能由阶段变更产生；允许建单即终态等于绕过规则。
8. **赢单率允许手改**：`opportunities.win_rate` 可空，**NULL = 跟随阶段默认值**，非空 = 手工值。改阶段时**不覆盖**手工值。响应同时给 `win_rate`（生效值：手工值或阶段默认）与 `win_rate_manual`（是否手工填过），编辑表单据此决定是否把输入框留空显示「跟随阶段」。
9. **`won_at` / `lost_reason_id` / `lost_note` 只能由 `POST /opportunities/{id}/stage` 写**，`PATCH` 不接受它们（`extra="forbid"` → 422）。
10. **重开终态**（`won`/`lost` → 任一推进阶段）：限 `manager`/`admin`（403），必须填 `note`（400），同一事务写 history；重开时清空 `won_at` / `lost_reason_id` / `lost_note`。
11. **删除机会**：仅 `manager`/`admin`（403），软删（`deleted_at`），重复删除 404。理由与客户删除同口径；软删保证阶段历史与报表不会因为一次误删丢掉整段漏斗。
12. **阶段变更不碰 `customers.last_activity_at`**（spec §3.3 的三条维护规则之外一律不动）。测试要钉住这一条——"有交互就刷新"是最容易顺手写坏的一处。
13. **同一阶段再提交**是 400 `invalid_value`「机会已处于该阶段」，不写空 history。
14. **阶段历史不单独开读接口**：`GET /customers/{id}/timeline` 属 P3（spec §5 合并三类来源），P2 只负责写对。测试直接读表验证。
15. **看板用专用接口** `GET /opportunities/board`：按六个阶段分组，每列返回 `total` / `amount_total`（全量聚合）与最多 200 条 `items`，避免"拉 200 条再前端分组"在数据变多后悄悄丢单。这是 P2 相对 spec §5 端点清单**唯一新增**的端点，理由记录在此。
16. **机会列表的 `keyword`** 命中机会名称、竞争对手、**及所属客户名称**（spec §5 说机会字段搜索"留给后续阶段"，P2 就是那个阶段）；`date_from`/`date_to` 筛 `expected_close_date`（整天，闭区间）。
17. **负责人同步 seam**：实现在 `opportunities.service.sync_opportunity_owner(db, *, customer_id, owner_id)`，只改**未关闭**（`stage NOT IN ('won','lost')`）的机会，已关闭的保留原负责人（历史业绩归属）。P1 尚无领取/分配/转移接口（属 P4），所以本函数在 P2 没有调用方——**它就位是为了让 P4 的领取/分配/转移在同一事务里调用，绝不允许 P4 自己另写一遍**。测试直接针对该函数（它是真实存在、被文档约定调用的公共 seam，不是假场景）。

`backend/app/modules/lost_reasons/models.py`：

```python
"""输单原因字典（design §3.10）。

字典表而不是自由文本：输单原因要作为报表维度（§7 按 `lost_reason_id` 分组），
自由文本在报表里会变成"价格高 / 价格太高 / 太贵"三行。

停用（`active=false`）与删除是两件事：历史机会还指着某条原因，硬删会让报表的
输单原因分组整块消失，所以 P2 只提供"停用"，不提供删除。
"""

from sqlalchemy import BigInteger, Boolean, Integer, String, text
from sqlalchemy.orm import Mapped, mapped_column

from app.db.base import Base, TimestampMixin


class LostReason(Base, TimestampMixin):
    __tablename__ = "lost_reasons"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    # unique 走命名约定，约束名是 uq_lost_reasons_name（迁移里显式写出同名约束）
    name: Mapped[str] = mapped_column(String(64), unique=True, nullable=False)
    sort_order: Mapped[int] = mapped_column(
        Integer, nullable=False, default=0, server_default=text("0")
    )
    # server_default 是给 ORM 之外的写入兜底（导入脚本、运维手插）：
    # 只有 Python 侧 default 时，裸 INSERT 会直接撞 NOT NULL。
    active: Mapped[bool] = mapped_column(
        Boolean, nullable=False, default=True, server_default=text("true")
    )
```

`backend/app/modules/lost_reasons/service.py`：

```python
"""输单原因字典服务。

P2 只有三个入口：列表（选择器数据源）、创建（种子脚本用）、按 id 取（阶段变更时
校验 `lost_reason_id` 真实存在）。管理端的增删改属 P5 后台，此处不做。
"""

from sqlalchemy import select
from sqlalchemy.orm import Session

from app.core.errors import ConflictError, InvalidValueError, NotFoundError
from app.modules.lost_reasons.models import LostReason
from app.modules.lost_reasons.schemas import LostReasonCreate


def _clean_name(name: str | None) -> str:
    """strip 后不能为空。

    schema 的 ``min_length=1`` 拦不住 ``"   "``；空名字在输单原因下拉框里就是一行
    看不见的空白，选项点了也不知道代表了什么。
    """
    cleaned = (name or "").strip()
    if not cleaned:
        raise InvalidValueError("输单原因不能为空")
    return cleaned


def _ensure_name_free(db: Session, name: str) -> None:
    """重名是 409（与现有数据冲突），不是静默覆盖。数据库唯一索引是第二道防线。"""
    exists = db.execute(
        select(LostReason.id).where(LostReason.name == name)
    ).first()
    if exists is not None:
        raise ConflictError("输单原因已存在")


def list_lost_reasons(
    db: Session, *, include_inactive: bool = False
) -> list[LostReason]:
    """按 ``sort_order`` 升序返回；默认只给启用中的原因（下拉框直接用这个顺序）。"""
    stmt = select(LostReason)
    if not include_inactive:
        stmt = stmt.where(LostReason.active.is_(True))
    return list(
        db.execute(stmt.order_by(LostReason.sort_order, LostReason.id))
        .scalars()
        .all()
    )


def get_lost_reason(db: Session, reason_id: int) -> LostReason:
    """按 id 取。不存在抛 404——阶段变更里一个不存在的 `lost_reason_id` 是参数错，
    不是"外键冲突"，不能拖到 commit 时才变成 500。"""
    reason = db.get(LostReason, reason_id)
    if reason is None:
        raise NotFoundError("输单原因不存在")
    return reason


def create_lost_reason(db: Session, payload: LostReasonCreate) -> LostReason:
    name = _clean_name(payload.name)
    _ensure_name_free(db, name)
    reason = LostReason(
        name=name, sort_order=payload.sort_order, active=payload.active
    )
    db.add(reason)
    db.commit()
    db.refresh(reason)
    return reason
```

```python
而不是另加 `win_rate_manual` 列，是因为"有没有手改过"恰好等于"这一列是不是空"，
```

```python
class StageHistory(Base, TimestampMixin):
    """阶段变更流水（design §3.7）。

    这是漏斗与成交周期报表的**唯一数据来源**，所以只追加、不修改：任何一次阶段
    变更（含创建）都必须留一行，`amount_snapshot` 记的是变更当刻的金额——机会金额
    之后还会被改，报表要按当时的值算，不能 join 回 opportunities 取现值。

    ``from_stage`` 为空的唯一场景是创建（从"不存在"进入首个阶段），因此
    "这一行是不是创建"的判断就是 ``from_stage IS NULL``，不需要额外的 action 列。
    """

    __tablename__ = "stage_histories"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    opportunity_id: Mapped[int] = mapped_column(
        BigInteger, ForeignKey("opportunities.id"), nullable=False
    )
    from_stage: Mapped[str | None] = mapped_column(String(16), nullable=True)
    to_stage: Mapped[str] = mapped_column(String(16), nullable=False)
    amount_snapshot: Mapped[Decimal | None] = mapped_column(
        Numeric(14, 2), nullable=True
    )
    note: Mapped[str | None] = mapped_column(Text, nullable=True)
    operator_id: Mapped[int | None] = mapped_column(
        BigInteger, ForeignKey("users.id"), nullable=True
    )
    changed_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now(), nullable=False
    )

    __table_args__ = (
        Index(
            "ix_stage_histories_opportunity_id_changed_at",
            "opportunity_id",
            "changed_at",
        ),
        CheckConstraint(
            f"from_stage IS NULL OR from_stage IN {_STAGE_SQL}",
            name="from_stage",
        ),
        CheckConstraint(f"to_stage IN {_STAGE_SQL}", name="to_stage"),
    )
```

```python
"""机会的请求/响应模型。

两道刻意的"拒绝"：

- ``extra="forbid"`` + **`OpportunityUpdate` 里没有 `stage`**：改阶段必须走
  ``POST /opportunities/{id}/stage``，这样 history 才不可能被绕过；
- ``OpportunityCreate`` 里没有 `owner_id`：机会负责人从客户负责人继承（§3.5），
  让请求体指定负责人等于允许"机会挂在别人名下"而客户不在。

``win_rate`` 在请求里可空：显式传 `null` 是"回到跟随阶段"，不传是"保持原值"
（PATCH 语义）——这两种"空"的区别靠 `model_dump(exclude_unset=True)` 表达。
"""

from datetime import date, datetime
from decimal import Decimal
from typing import Any

from pydantic import BaseModel, ConfigDict, Field, model_validator

from app.modules.opportunities.models import STAGE_WIN_RATES

# 派生字段：不是 ORM 列，由 model_validator 从关系里补出来
_DERIVED_FIELDS = (
    "customer_name",
    "owner_name",
    "lost_reason_name",
    "win_rate",
    "win_rate_manual",
)


class OpportunityCreate(BaseModel):
    model_config = ConfigDict(extra="forbid")

    customer_id: int
    name: str = Field(min_length=1, max_length=200)
    stage: str = "contact"
    amount: Decimal = Field(
        default=Decimal("0"), ge=0, max_digits=14, decimal_places=2

    expected_close_date: date | None = None
    competitor: str | None = Field(default=None, max_length=200)
    win_rate: int | None = Field(default=None, ge=0, le=100)


class OpportunityUpdate(BaseModel):

    没有 stage（走 /stage）、没有 customer_id（机会不能搬家）、没有 owner_id
    （跟随客户负责人）、没有 won_at / lost_reason_id / lost_note（终态字段只能由
    阶段变更写）。这些字段被提交时 ``extra="forbid"`` 会直接 422。
    """

    model_config = ConfigDict(extra="forbid")

    name: str | None = Field(default=None, min_length=1, max_length=200)
    amount: Decimal | None = Field(
        default=None, ge=0, max_digits=14, decimal_places=2

    expected_close_date: date | None = None
    competitor: str | None = Field(default=None, max_length=200)

    # 重开终态时必须填（service 校验），平时可空；写进 stage_histories.note
    note: str | None = None
    lost_reason_id: int | None = None
    lost_note: str | None = None


class OpportunityRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    customer_id: int
    customer_name: str
    name: str
    stage: str
    amount: Decimal
    expected_close_date: date | None
    competitor: str | None
    owner_id: int
    owner_name: str
    # 生效的赢单率：手工值为准，没填过就用阶段默认值
    win_rate: int
    # 前端据此决定编辑框是留空（跟随阶段）还是显示手工值
    win_rate_manual: bool
    lost_reason_id: int | None
    lost_reason_name: str | None
    lost_note: str | None
    won_at: datetime | None
    created_at: datetime
    updated_at: datetime

    @model_validator(mode="before")
    @classmethod
    def _derive_joined_fields(cls, data: Any) -> Any:
        """把关系表上的姓名与"生效赢单率"摆成键。

        不用 ``computed_field``：``from_attributes`` 只按字段名读同一个对象的属性，
        读不到关系另一张表上的列。三个关系都是 ``lazy="raise"``，必须由服务层
        ``joinedload`` 预加载（漏了会立刻报错而不是静默 N+1）。
        """
        if isinstance(data, (dict, cls)):
            return data
        customer = getattr(data, "customer", None)
        owner = getattr(data, "owner", None)
        lost_reason = getattr(data, "lost_reason", None)
        stored_win_rate = data.win_rate
        values = {
            field: getattr(data, field)
            for field in cls.model_fields
            if field not in _DERIVED_FIELDS
        }
        values["customer_name"] = customer.name if customer is not None else ""
        values["owner_name"] = owner.display_name if owner is not None else ""
        values["lost_reason_name"] = (
            lost_reason.name if lost_reason is not None else None
        )
        values["win_rate"] = (
            stored_win_rate
            if stored_win_rate is not None
            else STAGE_WIN_RATES[data.stage]
        )
        values["win_rate_manual"] = stored_win_rate is not None
        return values


class BoardColumnRead(BaseModel):
    stage: str
    total: int
    amount_total: Decimal
    items: list[OpportunityRead]


class BoardRead(BaseModel):
    columns: list[BoardColumnRead]
```

`backend/app/modules/opportunities/service.py`：

```python
"""机会服务。

作用域规则**不在这里定义**，而是组合 P1 的单一入口：可见机会 = 可见客户名下的
机会。写成 ``Opportunity.customer_id.in_(customer_query(actor).with_only_columns(Customer.id))``
而不是 join，是为了让"可见性只有一个真值源"在代码里一眼可见——评审能 grep 到
`customer_query`，而不是面对一个自己拼的 join 条件。

写入路径同理：先 ``get_customer``（403/404 分开），再
``assert_customer_writable``（公海只读）。机会模块不写第三套权限判断。
"""

from dataclasses import dataclass
from datetime import date
from decimal import Decimal

from sqlalchemy import ColumnElement, Select, func, or_, select
from sqlalchemy.orm import Session, joinedload

from app.core.errors import ForbiddenError, InvalidValueError, NotFoundError
from app.core.text import LIKE_ESCAPE, contains_pattern
from app.db.scope import customer_query
from app.modules.customers.models import Customer
from app.modules.customers.service import get_customer
from app.modules.opportunities.models import (
    OPPORTUNITY_STAGES,
    Opportunity,
)
from app.modules.users.models import User

_SORTABLE = {
    "created_at": Opportunity.created_at,
    "updated_at": Opportunity.updated_at,
    "amount": Opportunity.amount,
    "expected_close_date": Opportunity.expected_close_date,
}

# 看板每列最多返回多少条：`total` 是全量聚合（页头显示真实条数），items 只给前 N 条。
# 200 与分页上限一致，前端能明确说"显示前 200 条"。
BOARD_COLUMN_LIMIT = 200


@dataclass(frozen=True)
class BoardColumn:
    """看板一列：全量聚合 + 前 N 条明细。"""

    stage: str
    total: int
    amount_total: Decimal
    items: list[Opportunity]


def _visible_conditions(
    actor: User, *, customer_id: int | None = None
) -> list[ColumnElement[bool]]:
    """机会可见性的唯一构造点：软删过滤 + 客户作用域（+ 可选的单客户过滤）。"""
    conditions: list[ColumnElement[bool]] = [
        Opportunity.deleted_at.is_(None),
        Opportunity.customer_id.in_(
            customer_query(actor).with_only_columns(Customer.id)
        ),
    ]
    if customer_id is not None:
        conditions.append(Opportunity.customer_id == customer_id)
    return conditions


def _visible_query(actor: User) -> Select:
    return select(Opportunity).where(*_visible_conditions(actor))


def _with_relations(stmt: Select) -> Select:
    """三个关系一律显式预加载（模型上是 lazy="raise"，漏了立刻报错）。"""
    return stmt.options(
        joinedload(Opportunity.customer),
        joinedload(Opportunity.owner),
        joinedload(Opportunity.lost_reason),
    )


def _load_full(db: Session, opportunity_id: int) -> Opportunity:
    """写完回读一次，带上三个关系。返回的对象可直接序列化成 OpportunityRead。"""
    return db.execute(
        _with_relations(select(Opportunity))
        .where(Opportunity.id == opportunity_id)
        .execution_options(populate_existing=True)
    ).scalar_one()


def _validate_filter_stage(stage: str | None) -> None:
    """筛选取值非法是 400（不是空列表）：空列表会把"参数拼错"显示成"没有数据"。"""
    if stage and stage not in OPPORTUNITY_STAGES:
        raise InvalidValueError(f"未知阶段：{stage}")


def get_opportunity(db: Session, actor: User, opportunity_id: int) -> Opportunity:
    """按作用域取单个机会：不存在 404，存在但看不到 403。

    作用域内查不到时做一次**裸 select 的存在性探针**（只取 id、限定未删除），
    用来把 403 与 404 分开——与 ``customers.service.get_customer`` 同一手法。
    """
    opportunity = db.execute(
        _with_relations(_visible_query(actor)).where(Opportunity.id == opportunity_id)
    ).scalar_one_or_none()
    if opportunity is not None:
        return opportunity
    exists = db.execute(
        select(Opportunity.id).where(
            Opportunity.id == opportunity_id, Opportunity.deleted_at.is_(None)
        )
    ).scalar_one_or_none()
    if exists is None:
        raise NotFoundError("机会不存在")
    raise ForbiddenError("无权查看该机会")


def list_opportunities(
    db: Session,
    actor: User,
    *,
    keyword: str | None = None,
    stage: str | None = None,
    customer_id: int | None = None,
    owner_id: int | None = None,
    date_from: date | None = None,
    date_to: date | None = None,
    page: int = 1,
    page_size: int = 20,
    sort: str = "-created_at",
) -> tuple[list[Opportunity], int]:
    """作用域内的机会分页。

    ``keyword`` 命中机会名称、竞争对手、以及**所属客户名称**（spec §5 说机会字段的
    搜索"留给后续阶段"，P2 就是那个阶段）。``date_from`` / ``date_to`` 筛
    ``expected_close_date``：它是 date 列，整天闭区间即可，不像 timestamptz 那样要
    换算本地零点；没填成交日的机会在用了日期筛选时不会出现（NULL 比较结果为未知）。
    """
    _validate_filter_stage(stage)
    if date_from is not None and date_to is not None and date_from > date_to:
        raise InvalidValueError("开始日期不能晚于结束日期")
    if customer_id is not None:
        # 筛一个看不见的客户应当 403，而不是返回空列表：空列表会被读成"这客户没机会"
        get_customer(db, actor, customer_id)

    stmt = select(Opportunity).where(
        *_visible_conditions(actor, customer_id=customer_id)
    )
    if keyword and keyword.strip():
        pattern = contains_pattern(keyword.strip())
        stmt = stmt.where(
            or_(
                Opportunity.name.ilike(pattern, escape=LIKE_ESCAPE),
                Opportunity.competitor.ilike(pattern, escape=LIKE_ESCAPE),
                Opportunity.customer_id.in_(
                    customer_query(actor)
                    .with_only_columns(Customer.id)
                    .where(Customer.name.ilike(pattern, escape=LIKE_ESCAPE))
                ),
            )
        )
    if stage:
        stmt = stmt.where(Opportunity.stage == stage)
    if owner_id is not None:
        stmt = stmt.where(Opportunity.owner_id == owner_id)
    if date_from is not None:
        stmt = stmt.where(Opportunity.expected_close_date >= date_from)
    if date_to is not None:
        stmt = stmt.where(Opportunity.expected_close_date <= date_to)

    total = db.execute(select(func.count()).select_from(stmt.subquery())).scalar_one()

    stmt = _with_relations(stmt)
    normalized = sort.strip() or "-created_at"
    descending = normalized.startswith("-")
    field = normalized.lstrip("-")
    column = _SORTABLE.get(field)
    if column is None:
        raise InvalidValueError(f"不支持的排序字段：{field}")
    # 第二排序键 id 保证翻页稳定（金额/日期相同的机会不会漏页或重页）
    stmt = stmt.order_by(
        column.desc() if descending else column.asc(), Opportunity.id
    )
    stmt = stmt.offset((page - 1) * page_size).limit(page_size)
    return list(db.execute(stmt).scalars().all()), int(total)


def board(
    db: Session, actor: User, *, customer_id: int | None = None
) -> list[BoardColumn]:
    """看板数据：固定六列，每列全量聚合 + 前 ``BOARD_COLUMN_LIMIT`` 条明细。

    不按分页拉全量再前端分组：机会数过 200 之后，前端分组会静默丢掉第 201 条以后
    的机会，而看板恰恰是用来看"有多少单在谈"的。列内按预计成交日升序、未填的排最后
    （P2 没有逾期概念，最早该成交的单排最前最有用）。
    """
    if customer_id is not None:
        get_customer(db, actor, customer_id)
    conditions = _visible_conditions(actor, customer_id=customer_id)

    stats = {
        stage: (int(total), Decimal(amount_total))
        for stage, total, amount_total in db.execute(
            select(
                Opportunity.stage,
                func.count(),
                func.coalesce(func.sum(Opportunity.amount), 0),
            )
            .where(*conditions)
            .group_by(Opportunity.stage)
        ).all()
    }

    columns: list[BoardColumn] = []
    for stage in OPPORTUNITY_STAGES:
        total, amount_total = stats.get(stage, (0, Decimal("0")))
        if total == 0:
            columns.append(
                BoardColumn(stage=stage, total=0, amount_total=Decimal("0"), items=[])
            )
            continue
        items = list(
            db.execute(
                _with_relations(select(Opportunity).where(*conditions))
                .where(Opportunity.stage == stage)
                .order_by(
                    Opportunity.expected_close_date.asc().nulls_last(),
                    Opportunity.id,
                )
                .limit(BOARD_COLUMN_LIMIT)
            )
            .scalars()
            .all()
        )
        columns.append(
            BoardColumn(
                stage=stage, total=total, amount_total=amount_total, items=items
            )
        )
    return columns
```

```python
# 库里的 NOT NULL 列：显式传 null 不能落库，按取值非法（400）而不是撞 500
_REQUIRED_FIELDS = {"name": "机会名称", "amount": "预计金额"}

# update 认的字段，与 schemas.OpportunityUpdate 一一对应（多一道白名单兜底）
UPDATABLE_FIELDS = frozenset(OpportunityUpdate.model_fields)


def _clean_name(name: str | None) -> str:
    """strip 后不能为空：空名字在列表里就是一行看不见的空白。"""
    cleaned = (name or "").strip()
    if not cleaned:
        raise InvalidValueError("机会名称不能为空")
    return cleaned


def _clean_optional(value: str | None) -> str | None:
    """竞争对手这类自由文本：全空白按没填处理，避免前端把空串写进库。"""
    if value is None:
        return None
    cleaned = value.strip()
    return cleaned or None


def _validate_stage_for_create(stage: str) -> None:
    """创建时只允许四个推进阶段。

    赢单要 `won_at`、输单要原因，这两个字段只能由阶段变更产生（Task 6）。允许建单
    即终态等于给了一条绕过规则的旁路，而且"新建一个已经输掉的机会"本身也没有
    业务含义。
    """
    if stage not in OPPORTUNITY_STAGES:
        raise InvalidValueError(f"未知阶段：{stage}")
    if stage in TERMINAL_STAGES:
        raise InvalidValueError(
            "新建机会只能从推进阶段开始；赢单/输单必须通过阶段变更产生"
        )


def _writable_customer(db: Session, actor: User, customer_id: int) -> Customer:
    """写入前必经：先按作用域取客户（403/404 分开），再判可写（公海只读）。"""
    customer = get_customer(db, actor, customer_id)
    assert_customer_writable(customer, actor)
    return customer


def create_opportunity(
    db: Session, actor: User, payload: OpportunityCreate
) -> Opportunity:
    """创建机会。

    负责人**只能**从客户继承（design §3.5「机会负责人与客户负责人一致」），请求体
    里没有 owner_id 这个字段（schema `extra="forbid"`）。因此公海客户（没有负责人）
    建不了机会——这不是遗漏，是 owner_id NOT NULL 与一致性规则的必然结果。

    创建本身也是一次"阶段从无到有"，所以同一事务里写第一条 history
    （`from_stage=None`）：否则「漏斗里有多少单进了初步接触」就少了一整段。
    """
    name = _clean_name(payload.name)
    _validate_stage_for_create(payload.stage)
    customer = _writable_customer(db, actor, payload.customer_id)
    if customer.owner_id is None:
        raise InvalidValueError("客户未分配负责人，请先领取或分配后再新建机会")

    opportunity = Opportunity(
        customer_id=customer.id,
        name=name,
        stage=payload.stage,
        amount=payload.amount,
        expected_close_date=payload.expected_close_date,
        competitor=_clean_optional(payload.competitor),
        owner_id=customer.owner_id,
        win_rate=payload.win_rate,
        created_by=actor.id,
    )
    db.add(opportunity)
    db.flush()  # 拿到自增 id，history 需要它
    db.add(
        StageHistory(
            opportunity_id=opportunity.id,
            from_stage=None,
            to_stage=opportunity.stage,
            amount_snapshot=opportunity.amount,
            note=None,
            operator_id=actor.id,
        )
    )
    db.commit()
    return _load_full(db, opportunity.id)


def update_opportunity(
    db: Session, actor: User, opportunity_id: int, payload: OpportunityUpdate
) -> Opportunity:
    """编辑机会字段。

    `stage` / `owner_id` / `won_at` / `lost_reason_id` 都不在白名单里（schema 已经
    `extra="forbid"`，这里再挡一次是给绕过 schema 的调用方留同一道门）。
    改金额**不**写 history：§3.7 的 history 只记阶段变更，金额的演变由报表按
    `amount_snapshot` 的时点快照体现，不靠 history 行。
    """
    opportunity = get_opportunity(db, actor, opportunity_id)
    _writable_customer(db, actor, opportunity.customer_id)

    changes = payload.model_dump(exclude_unset=True)
    unknown = set(changes) - UPDATABLE_FIELDS
    if unknown:
        raise InvalidValueError(f"不可更新的字段：{'、'.join(sorted(unknown))}")
    for field, label in _REQUIRED_FIELDS.items():
        if field in changes and changes[field] is None:
            raise InvalidValueError(f"{label}不能为空")
    if "name" in changes:
        changes["name"] = _clean_name(changes["name"])
    if "competitor" in changes:
        changes["competitor"] = _clean_optional(changes["competitor"])
    # win_rate 显式传 null 是合法动作：回到"跟随阶段默认值"
    for field, value in changes.items():
        setattr(opportunity, field, value)
    db.commit()
    return _load_full(db, opportunity.id)


def delete_opportunity(db: Session, actor: User, opportunity_id: int) -> None:
    """软删除：仅主管及以上，且必须在自己的可写范围内。

    软删而不是硬删：stage_histories 是漏斗与成交周期报表的唯一数据来源，硬删会让
    报表里整段历史凭空消失。已删的机会对接口表现为不存在（重复删除 404）。
    """
    from app.modules.users.models import ROLE_ADMIN, ROLE_MANAGER

    if actor.role not in (ROLE_ADMIN, ROLE_MANAGER):
        raise ForbiddenError("仅主管及以上可删除机会")
    opportunity = get_opportunity(db, actor, opportunity_id)
    _writable_customer(db, actor, opportunity.customer_id)
    opportunity.deleted_at = datetime.now(UTC)
    db.commit()


def sync_opportunity_owner(
    db: Session, *, customer_id: int, owner_id: int
) -> int:
    """把某客户名下**未关闭**机会的负责人改到新负责人。返回实际受影响行数。

    design §3.5：客户的领取、分配、转移在同一个事务内把该客户名下未关闭
    （`stage NOT IN ('won','lost')`）的机会一并改过去；已赢/已输的机会保留原负责人
    作为历史业绩归属——否则把三年前的成单算到新人头上，业绩报表就失真了。

    **本函数不 commit**：调用方（P4 的领取/分配/转移）必须与客户归属变更放在同一个
    事务里，否则会出现"客户已换人、在谈的机会还挂在旧人"的中间态。

    P2 没有调用方：P1 尚未实现领取/分配/转移（属 P4）。这里先落地并测试，是为了让
    P4 直接调用，而不是届时再凭记忆重写一遍规则（重写必然漏掉"未关闭"这半句）。
    """
    result = db.execute(
        update(Opportunity)
        .where(
            Opportunity.customer_id == customer_id,
            Opportunity.deleted_at.is_(None),
            Opportunity.stage.not_in(TERMINAL_STAGES),
            Opportunity.owner_id.is_distinct_from(owner_id),
        )
        .values(owner_id=owner_id)
    )
    return int(result.rowcount or 0)
```

```python
_REOPEN_ROLES = (ROLE_ADMIN, ROLE_MANAGER)


def _validate_stage_value(stage: str) -> None:
    if stage not in OPPORTUNITY_STAGES:
        raise InvalidValueError(f"未知阶段：{stage}")


def change_stage(
    db: Session, actor: User, opportunity_id: int, payload: StageChange
) -> Opportunity:
    """阶段变更：允许前进、后退、跨阶段跳转，每次都写一条 history。

    规则全部来自 design §3.6，逐条落在这里（路由层无法绕过：`PATCH` 不接受 stage，
    这是唯一入口）：

    - `won` / `lost` 是终态；**终态之间不能互转**——赢单后想改成输单，必须先重开到
      推进阶段，否则一条 history 会同时表达"赢过"和"输掉"，报表口径就乱了；
    - 重开终态限 `manager` / `admin`，且必须填原因（写进 history.note）；
    - 进 `lost` 必须选 `lost_reason_id`（原因不存在是 404，不是外键 500）；
    - 进 `won` 记 `won_at`；离开终态时把终态字段清干净，否则报表仍按旧 `won_at`
      把这单算成赢单；
    - 手工赢单率（`win_rate` 非空）**不覆盖**，自动值（NULL）继续跟随新阶段；
    - 不碰 `customers.last_activity_at`（§3.3 的三条同步点之外一律不动）。
    """
    _validate_stage_value(payload.stage)
    opportunity = get_opportunity(db, actor, opportunity_id)
    _writable_customer(db, actor, opportunity.customer_id)

    if opportunity.stage == payload.stage:
        raise InvalidValueError("机会已处于该阶段")
    note = (payload.note or "").strip() or None

    was_closed = opportunity.stage in TERMINAL_STAGES
    if was_closed:
        if actor.role not in _REOPEN_ROLES:
            raise ForbiddenError("仅主管及以上可重开已关闭的机会")
        if payload.stage in TERMINAL_STAGES:
            raise InvalidValueError(
                "已关闭的机会不能直接改为另一个终态，请先重开到推进阶段"
            )
        if note is None:
            raise InvalidValueError("重开机会必须填写重开原因")

    if payload.stage == "lost":
        if payload.lost_reason_id is None:
            raise InvalidValueError("输单必须选择输单原因")
        # 不存在的原因要给 404，而不是拖到 commit 时变成外键 500
        get_lost_reason(db, payload.lost_reason_id)
    elif payload.lost_reason_id is not None:
        raise InvalidValueError("只有输单阶段可以填写输单原因")

    if payload.stage == "won":
        opportunity.won_at = datetime.now(UTC)
        opportunity.lost_reason_id = None
        opportunity.lost_note = None
    elif payload.stage == "lost":
        opportunity.won_at = None
        opportunity.lost_reason_id = payload.lost_reason_id
        opportunity.lost_note = _clean_optional(payload.lost_note)
    else:
        opportunity.won_at = None
        opportunity.lost_reason_id = None
        opportunity.lost_note = None

    history = StageHistory(
        opportunity_id=opportunity.id,
        from_stage=opportunity.stage,   # 必须在改 stage 之前取
        to_stage=payload.stage,
        amount_snapshot=opportunity.amount,
        note=note,
        operator_id=actor.id,
    )
    opportunity.stage = payload.stage
    db.add(history)
    db.commit()
    return _load_full(db, opportunity.id)
```

```python
def _find_opportunity(db: Session, customer_id: int, name: str) -> int | None:
    """按（客户，机会名称）判重。

    软删的也跳过：删掉再建同名是合法操作，但种子脚本不该在每次执行时把用户**刚
    删掉**的机会重新建出来——那会让"我删了它"变成"它又回来了"。
    """
    return db.execute(
        select(Opportunity.id).where(
            Opportunity.customer_id == customer_id, Opportunity.name == name
        )
    ).scalar_one_or_none()


def _seed_opportunities(
    db: Session,
    customers: dict[str, Customer],
    owners: dict[int, User],
    reasons: dict[str, LostReason],
) -> tuple[int, list[str], list[str]]:
    created: list[str] = []
    skipped: list[str] = []
    for spec in OPPORTUNITIES:
        label = f"{spec.customer}/{spec.name}"
        customer = customers.get(spec.customer)
        if customer is None or customer.owner_id is None:
            # 公海客户没有负责人，也就不可能有机会（§3.5）。种子不制造例外。
            skipped.append(label)
            continue
        if _find_opportunity(db, customer.id, spec.name) is not None:
            skipped.append(label)
            continue
        actor = owners[customer.owner_id]
        opportunity = create_opportunity(
            db,
            actor,
            OpportunityCreate(
                customer_id=customer.id,
                name=spec.name,
                amount=Decimal(spec.amount),
                expected_close_date=spec.expected_close_date,
                competitor=spec.competitor,
                win_rate=spec.win_rate,
            ),
        )
        for stage in STAGE_PATH[spec.stage]:
            payload: dict[str, object] = {"stage": stage}
            if stage == "lost":
                payload["lost_reason_id"] = reasons[str(spec.lost_reason)].id
                payload["lost_note"] = spec.lost_note
            change_stage(db, actor, opportunity.id, StageChange(**payload))
        created.append(label)
    return len(created), created, skipped
```

```ts
/**
 * 金额展示：千分位 + 两位小数。
 *
 * `Number()` 只用于**展示**（toLocaleString），不参与任何计算；计算与比较一律
 * 交给后端的 Decimal。金额在 wire 上是字符串，就是为了不让浮点误差进到业务里。
 */
export function formatAmount(value: string | null | undefined): string {
  if (value === null || value === undefined || value === "") return "—";
  const numeric = Number(value);
  if (!Number.isFinite(numeric)) return value;
  return numeric.toLocaleString("zh-CN", {
    minimumFractionDigits: 2,
    maximumFractionDigits: 2,
  });
}

/** 日期在 wire 上是 ISO 日期/时间串；只取年月日展示，空值给破折号。 */

  if (!value) return "—";
  return value.slice(0, 10);
```

```ts
import { api } from "./client";
import type { Board, LostReason, Opportunity, Page } from "./types";

export interface OpportunityListParams {
  keyword?: string;
  stage?: string;
  customer_id?: number;
  page?: number;
  page_size?: number;
  sort?: string;
}

export function listOpportunities(params: OpportunityListParams) {
  const query = new URLSearchParams();
  if (params.keyword) query.set("keyword", params.keyword);
  if (params.stage) query.set("stage", params.stage);
  if (params.customer_id !== undefined) query.set("customer_id", String(params.customer_id));
  if (params.sort) query.set("sort", params.sort);
  query.set("page", String(params.page ?? 1));
  query.set("page_size", String(params.page_size ?? 20));
  return api.get<Page<Opportunity>>(`/api/v1/opportunities?${query.toString()}`);
}

/**
 * 创建体：**没有 `owner_id`**——机会负责人从客户负责人继承（后端 schema
 * `extra="forbid"` 会 422）。`amount` 用字符串，避免浮点在网络上来回转换。
 */
export interface OpportunityCreateBody {
  customer_id: number;
  name: string;
  stage?: string;
  amount?: string;
  expected_close_date?: string | null;
  competitor?: string | null;
  win_rate?: number | null;
}

/**
 * 更新体：**没有 `stage` / `owner_id` / `won_at` / `lost_reason_id`**。
 * 阶段变更必须走 `changeStage`（后端只在那条路径上写 stage_histories），
 * 类型层面就把这条规则固化下来，比注释可靠。
 */
export interface OpportunityUpdateBody {
  name?: string;
  amount?: string;
  expected_close_date?: string | null;
  competitor?: string | null;
  win_rate?: number | null;
}

export interface StageChangeBody {
  stage: string;
  note?: string | null;
  lost_reason_id?: number | null;
  lost_note?: string | null;
}

export function createOpportunity(body: OpportunityCreateBody) {
  return api.post<Opportunity>("/api/v1/opportunities", body);
}

export function getOpportunity(id: number) {
  return api.get<Opportunity>(`/api/v1/opportunities/${id}`);
}

export function updateOpportunity(id: number, body: OpportunityUpdateBody) {
  return api.patch<Opportunity>(`/api/v1/opportunities/${id}`, body);
}

export function deleteOpportunity(id: number) {
  return api.del(`/api/v1/opportunities/${id}`);
}

/** 阶段变更的唯一入口：每次调用后端都会写一条 stage_histories。 */
export function changeStage(id: number, body: StageChangeBody) {
  return api.post<Opportunity>(`/api/v1/opportunities/${id}/stage`, body);
}

export function getBoard(params: { customer_id?: number } = {}) {
  const query = new URLSearchParams();
  if (params.customer_id !== undefined) query.set("customer_id", String(params.customer_id));
  const suffix = query.toString();
  return api.get<Board>(`/api/v1/opportunities/board${suffix ? `?${suffix}` : ""}`);
}

/** 输单原因下拉的数据源：后端只返回启用中的条目，按 sort_order 排好。 */
export function listLostReasons() {
  return api.get<LostReason[]>("/api/v1/lost-reasons");
}
```

**交互口径（spec §6.2 第 4 条 + §6.3）：**
- 桌面：卡片 `draggable`，`onDrop` 落在哪列就是哪一列；**不做乐观移动**——服务端成功前卡片留在原列，失败就自然"回弹"（比乐观移动 + 回滚少一套状态，也不会出现"闪一下又跳回去"）。
- 拖到「输单」：必须选原因，弹窗；拖动的机会原本在终态（重开）：必须填原因，弹窗；其余直接提交。
- 手机（<768px）：不启用拖拽（触屏误触率高），点卡片弹同一个弹窗选阶段。
- 终态之间不能互转（后端 400）：重开时弹窗只给四个推进阶段，前端先一步避免这个错误。

```tsx
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import { useState } from "react";

import { errorMessage } from "../api/client";
import { changeStage, listLostReasons } from "../api/opportunities";
import type { Opportunity } from "../api/types";
import {
  OPEN_STAGES,
  STAGE_LABELS,
  STAGE_ORDER,
  isTerminalStage,
} from "../constants/opportunityLabels";
import { Field, TextArea } from "./Field";
import { Modal } from "./Modal";

interface Props {
  opportunity: Opportunity;
  /** 拖拽落到的目标阶段；直接点卡片时传当前阶段。 */
  initialStage: string;
  onClose: () => void;
}

/**
 * 阶段变更弹窗：拖拽、点选、移动端三种入口共用。
 *
 * 三种情况必须有额外输入，否则后端的 400 会在用户眼前变成一条看不懂的错误：
 * 进「输单」要选原因；从终态重开要填原因；终态之间不能互转（重开时只给推进阶段）。
 */
export function StageChangeModal({ opportunity, initialStage, onClose }: Props) {
  const queryClient = useQueryClient();
  const [stage, setStage] = useState(initialStage);
  const [note, setNote] = useState("");
  const [lostReasonId, setLostReasonId] = useState("");
  const [lostNote, setLostNote] = useState("");
  const [error, setError] = useState<string | null>(null);

  const reasonsQuery = useQuery({
    queryKey: ["lost-reasons"],
    queryFn: listLostReasons,
    enabled: stage === "lost",
  });

  const reopening = isTerminalStage(opportunity.stage);
  // 重开只能回到推进阶段（后端拒绝终态互转）；正常变更时排除当前阶段
  const availableStages: readonly string[] = reopening
    ? OPEN_STAGES
    : STAGE_ORDER.filter((value) => value !== opportunity.stage);

  const mutation = useMutation({
    mutationFn: () =>
      changeStage(opportunity.id, {
        stage,
        note: note.trim() === "" ? null : note.trim(),
        lost_reason_id: stage === "lost" ? Number(lostReasonId) : null,
        lost_note: stage === "lost" && lostNote.trim() !== "" ? lostNote.trim() : null,
      }),
    onMutate: () => setError(null),
    onSuccess: async () => {
      await queryClient.invalidateQueries({ queryKey: ["board"] });
      await queryClient.invalidateQueries({ queryKey: ["opportunities"] });
      onClose();
    },
    onError: (err) => setError(errorMessage(err, "阶段变更失败，请重试")),
  });

  const blocked =
    stage === opportunity.stage ||
    (stage === "lost" && lostReasonId === "") ||
    (reopening && note.trim() === "");

  return (
    <Modal title="推进阶段" onClose={onClose}>
      <div className="space-y-3">
        <p className="break-words text-sm text-slate-600">
          {opportunity.name} · 当前：{STAGE_LABELS[opportunity.stage] ?? opportunity.stage}
```

```tsx
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import { useState } from "react";
import { Link } from "react-router-dom";

import { errorMessage } from "../api/client";
import { changeStage, getBoard } from "../api/opportunities";
import type { Opportunity } from "../api/types";
import { QueryError } from "../components/QueryError";
import { StageChangeModal } from "../components/StageChangeModal";
import {
  STAGE_BADGE_CLASS,
  STAGE_LABELS,
  formatAmount,
  formatDate,
  isTerminalStage,
} from "../constants/opportunityLabels";

export default function OpportunityBoardPage() {
  const queryClient = useQueryClient();
  const [dragging, setDragging] = useState<Opportunity | null>(null);
  const [dragOverStage, setDragOverStage] = useState<string | null>(null);
  const [modal, setModal] = useState<{ opportunity: Opportunity; stage: string } | null>(null);

  const query = useQuery({ queryKey: ["board"], queryFn: () => getBoard() });

  const move = useMutation({
    mutationFn: ({ id, stage }: { id: number; stage: string }) => changeStage(id, { stage }),
    onSuccess: async () => {
      await queryClient.invalidateQueries({ queryKey: ["board"] });
      await queryClient.invalidateQueries({ queryKey: ["opportunities"] });
    },
  });

  /**
   * 落点处理：只在**服务端确认后**才换列（不做乐观移动）。
   * 需要额外输入的两类（进输单、从终态重开）先弹窗，由弹窗提交。
   */
  function handleDrop(stage: string) {
    const opportunity = dragging;
    setDragging(null);
    setDragOverStage(null);
    if (opportunity === null || opportunity.stage === stage) return;
    if (stage === "lost" || isTerminalStage(opportunity.stage)) {
      setModal({ opportunity, stage });
      return;
    }
    move.mutate({ id: opportunity.id, stage });
  }

  if (query.isLoading) return <p className="text-sm text-slate-500">加载中…</p>;
  if (query.isError) {
    return (
      <QueryError
        error={query.error}
        fallback="看板加载失败，请重试"
        onRetry={() => void query.refetch()}
      />
    );
  }

  return (
    <div className="space-y-3">
      <div className="flex flex-wrap items-center gap-2">
        <h1 className="text-base font-semibold text-slate-900">机会看板</h1>
        <Link
          to="/opportunities"
          className="rounded-md border border-slate-300 px-2.5 py-1 text-sm hover:bg-slate-100"
        >
          列表视图
        </Link>
        <p className="w-full text-xs text-slate-500 sm:w-auto">
          桌面可直接拖动卡片改阶段；手机上点卡片选阶段。落位后由服务端确认，失败会自动回到原列。
        </p>
      </div>

      {move.isError ? (
        <p className="break-words text-sm text-red-600">
          {errorMessage(move.error, "阶段变更失败，请重试")}
        </p>
      ) : null}

      {/* 手机横向滚动分列（spec §6.3）：不换成"按阶段叠起来的列表"，
          否则"看板上各阶段有多少单"在手机上就看不见了。 */}
      <div className="flex gap-3 overflow-x-auto pb-2">
        {(query.data?.columns ?? []).map((column) => (
          <section
            key={column.stage}
            onDragOver={(event) => {
              event.preventDefault();
              setDragOverStage(column.stage);
            }}
            onDragLeave={() => setDragOverStage((prev) => (prev === column.stage ? null : prev))}
            onDrop={(event) => {
              event.preventDefault();
              handleDrop(column.stage);
            }}
            className={`flex min-w-[240px] flex-1 flex-col gap-2 rounded-lg border p-2 ${
              dragOverStage === column.stage
                ? "border-brand-400 bg-brand-50"
                : "border-slate-200 bg-slate-50"
            }`}
          >
            <header className="flex items-center justify-between gap-2 px-1">
              <span
                className={`inline-flex rounded px-1.5 py-0.5 text-xs font-medium ${
                  STAGE_BADGE_CLASS[column.stage] ?? "bg-slate-100 text-slate-700"
                }`}
              >
                {STAGE_LABELS[column.stage] ?? column.stage}
              </span>
              <span className="shrink-0 text-xs text-slate-500">
                {column.total} 条 · {formatAmount(column.amount_total)}
              </span>
            </header>

            {column.items.map((item) => (
              <article
                key={item.id}
                draggable
                onDragStart={(event) => {
                  // text/plain 只是为了让 Firefox 认这次拖拽；真正的数据在 React state 里
                  event.dataTransfer.setData("text/plain", String(item.id));
                  event.dataTransfer.effectAllowed = "move";
                  setDragging(item);
                }}
                onDragEnd={() => {
                  setDragging(null);
                  setDragOverStage(null);
                }}
                onClick={() => setModal({ opportunity: item, stage: item.stage })}
                className={`cursor-pointer space-y-1 rounded-md border border-slate-200 bg-white p-2 text-sm shadow-sm hover:border-brand-300 ${
                  dragging?.id === item.id ? "opacity-50" : ""
                }`}
              >
                <p className="break-words font-medium text-slate-900">{item.name}</p>
                <p className="break-words text-xs text-slate-500">{item.customer_name}</p>
                <p className="text-xs text-slate-600">
                  {formatAmount(item.amount)} · {formatDate(item.expected_close_date)}
                </p>
                <p className="text-xs text-slate-400">
                  {item.owner_name} · {item.win_rate}%
                  {item.win_rate_manual ? "（手）" : ""}
                </p>
              </article>
            ))}

            {column.total > column.items.length ? (
              <p className="px-1 text-xs text-slate-400">
                仅显示前 {column.items.length} 条，共 {column.total} 条
              </p>
            ) : null}
            {column.total === 0 ? (
              <p className="px-1 py-4 text-center text-xs text-slate-400">空</p>
            ) : null}
          </section>
        ))}
      </div>

      {modal ? (
        <StageChangeModal
          opportunity={modal.opportunity}
          initialStage={modal.stage}
          onClose={() => setModal(null)}
        />
      ) : null}
    </div>
  );
}
```

```python
def test_opportunity_lifecycle_end_to_end(client, db):
    """P2 冒烟：登录 → 建客户 → 建机会 → 逐阶段推到赢单 → 看板口径一致。

            json={"stage": stage},

        assert resp.status_code == 200, resp.text
        assert resp.json()["stage"] == stage

    won = client.post(
        f"/api/v1/opportunities/{body['id']}/stage",

        json={"stage": "won"},

    assert won.json()["won_at"] is not None
    assert won.json()["win_rate"] == 100

    assert board.status_code == 200
    columns = {column["stage"]: column for column in board.json()["columns"]}

    assert columns["won"]["amount_total"] == "123456.78"
    assert columns["contact"]["total"] == 0

        f"/api/v1/opportunities/{body['id']}",
```
