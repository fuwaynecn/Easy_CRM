# Easy CRM P3 实施计划（跟进记录 · 待办 · 首页三块 · 客户时间线）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让销售能记录每一次跟进、安排并完成下一步待办，并在首页看到「今天该做什么」，在客户详情看到该客户发生了什么（跟进 + 阶段变更混排的时间线）。

**Architecture:** 沿用 P1/P2 的模块化单体，新增 `app/modules/activities/`、`app/modules/followups/`、`app/modules/timeline/`、`app/modules/home/`，外加只放常量的 `app/modules/pools/`（P4 换成读 `pool_rules` 表）。可见性**完全继承客户**：所有读取从 `app/db/scope.py` 的 `customer_query(actor)` 起步，写前必过 `get_customer` + `assert_customer_writable`，新模块不另建一套作用域规则。`customers.last_activity_at` 的写入收敛到 `customers.service.mark_customer_activity()` 一个 seam（`GREATEST` 语义），只有「新建 activity」与 P4 的「领取/转移」调用它。

**Tech Stack:** 沿用 P1/P2，不新增任何依赖。后端 Python 3.12 / FastAPI / SQLAlchemy 2.0（同步）/ Alembic / Pydantic v2 / PostgreSQL 16；前端 React 18 + TypeScript + Vite 5 + Tailwind 3.4 + TanStack Query 5。时间格式化用浏览器内置 `Intl.DateTimeFormat`，不引入 dayjs/date-fns。

**Spec:** `docs/superpowers/specs/2026-10-29-easy-crm-design.md`（§3.3、§3.8、§3.9、§4.5、§5、§6.1、§6.3）

## Global Constraints

P1/P2 的全局约束**全部继续有效**，逐条列在这里，执行时不得违反：

- 数据库与接口时间一律 UTC（`timestamptz` / ISO 8601 带偏移）；「今天」「逾期」等业务判断一律按 `Asia/Shanghai` 换算后判断。
- 金额 `numeric(14,2)`；**线上形式是定点字符串**（`"1234.50"`），前端只格式化展示，不做 `Number()` → `toFixed()` 往返。
- **所有客户相关读取必须从 `app/db/scope.py` 的 `customer_query(actor)` 起步**；活动/待办的可见性用 `X.customer_id.in_(customer_query(actor).with_only_columns(Customer.id))` 表达，禁止自己拼可见性条件。
- **写前必过 `assert_customer_writable(customer, actor)`**（公海客户对 sales/manager 只读）。
- 越权 403；不存在 404；取值非法 400；与现有数据冲突 409；错误体统一 `{code, message, detail}`。
- 软删用 `deleted_at`，所有列表/详情过滤 `deleted_at IS NULL`；**时间线是唯一例外**（见裁定 1）。
- 命名：Python snake_case；前端本地标识符 camelCase，但**镜像后端 wire 字段的 DTO 保持 snake_case**（`frontend/src/api/types.ts`）。
- 数据库约束必须显式命名（`CheckConstraint(name=...)`、索引显式 `name=`），命名约定在 `app/db/base.py`。
- 测试跑真实 PostgreSQL（`easycrm_test`），禁止 SQLite；**不许只断言状态码**（要断言 `code` 与业务字段）；不许造假用户/假场景去测未实现的功能。
- 前端无自动化测试框架（spec §12）：前端任务的「红/绿」由 `tsc --noEmit` + `vite build` 承担，外加手测清单。
- 后端测试必须先红后绿：先跑一次失败，把**原始输出**贴进报告，再实现。每个后端任务都要一次「改坏→红→改回→绿」的变异验证。
- **同一时刻只能有一个 pytest 进程**：测试库 `easycrm_test` 每个 session 都会 drop/create schema，两个 pytest 并发会互相拆表（实测会成片 `relation "users" does not exist`）。要并发跑，只能跑不同 `-k` 之外的单进程串行。
- 一次只有一个实现者（共享 git 索引）；实现者/评审者不得再派子代理。

## P3 裁定（Wayne 已确认，执行时不要再讨论）

**已确认的 6 项**

1. **时间线边界**：已软删的机会、已删除的联系人、已停用的用户，其历史事件**照常显示**，行内标注来源状态（`opportunity_deleted` / `contact_deleted` / `operator_disabled`）；**不提供跳转到已删机会**。理由：时间线是「发生过什么」的记录，隐藏会让「这单推进到过商务谈判」凭空消失。代价：时间线读取**故意绕过**机会与联系人的软删过滤（这是本计划唯一允许读已删行的地方）。
2. **首页「即将进公海」**：忠于 spec §4.2，阈值 `INACTIVE_DAYS(30) - RECYCLE_NOTICE_DAYS(3) = 27` 天无活动，且满足两条豁免（名下无未关闭机会、无 pending 待办）。常量集中在 `app/modules/pools/rules.py`，UI 标注「规则将于 P4 可配置」。P4 只把常量换成读 `pool_rules`。**不按交接简报的「写死 30 天、不加豁免」**——那会让在谈客户出现在预警里，P4 上线时首页内容突变。
3. **待办可见性**：与客户可见性一致（主管可读本部门客户名下的待办）；「我的待办」按 `join customers` 后 `customers.owner_id = me`，**不给待办加负责人字段**。
4. **成交额口径**：读 `stage_histories.amount_snapshot`（时点值），不读 `opportunities.amount` 现值。时间线的阶段变更行展示快照金额；P5 报表沿用此口径。
5. **跟进/待办权限**：本人可改可删；主管可删本部门；admin 全部；一律软删（两张表都加 `deleted_at`）。`follow_ups` 另有 `status='cancelled'` 表示「不做了」（留痕），与 DELETE（误建，软删后不再出现）语义不同。
6. **时间线第三类来源**：`owner_change_logs` 表在代码里**不存在**（属 P4），P3 只合并 `activities` + `stage_histories`；响应 `type` 枚举**预留** `owner_change`，P4 建表后接入，前端契约不变。

**实施级裁定（本计划新增，评审时按此验收）**

7. **`/home` 是 P3 唯一新增的端点**。spec §5 的端点清单没有首页数据接口，但 §6.1 要求 `/` 三块——与 P2 加 `/opportunities/board` 同理，记录理由：三块各自有聚合与豁免条件，塞进客户列表会变成三次全量拉取。
8. **`last_activity_at` 只在「新建 activity」更新**，编辑/删除 activity **一律不碰**（spec §3.3 只有三个同步点，删除后不回算）。代价：把一条跟进改到更晚的时间，回收时钟仍按原值走——记进交接文档的已知限制，P4 若要精确再补回算。
9. **待办的「本人」= 客户当前负责人，跟进的「本人」= 记录创建者**。理由：spec §3.9 明确「客户转给谁，待办就归谁」，用 `created_by` 会让接手人无法处理前任留下的待办；而跟进是「某人说过的原话」性质的证词，只有写的人能改。
10. **`follow_ups` 的完成只能走 `POST /follow_ups/{id}/done`**，`PATCH` 传 `status="done"` 是 400。理由：完成要可选地生成 activity 并同事务更新 `last_activity_at`，混进通用 PATCH 会让「完成」有两种语义。
11. **跟进与待办的关联对象（`customer_id` / `contact_id` / `opportunity_id`）创建后不可改**（PATCH 白名单只有 `type` / `content` / `activity_at` / `due_at` / `content` / `status`）。关联错就删了重写，避免「改了联系人的跟进」这种审计黑洞。
12. **客户详情页增加「该客户的待办（pending）」小列表**。spec §4.5 要求完成待办可「顺便写条跟进」，但没有给出待办清单的页面位置（§6.1 只有首页三块）。最小可行落点：右栏联系人卡片之下，最多 5 条 pending，带「完成 / 取消」按钮与「+ 新建」。这是 P3 对 spec 的**一处显式补充**，不是遗漏。
13. **「即将进公海」不包含 `last_activity_at IS NULL` 的客户**。spec §4.2 的条件就是 `last_activity_at < ...`，NULL 不满足；P4 的回收任务同样不会回收「从未跟进过」的客户。这是 spec 的既有口径，P3 不改，记进交接文档（P4 若要覆盖，需同时改回收条件与预警）。
14. **时间线游标是不透明字符串**（`base64url("<occurred_at iso>|<type>|<id>")`），客户端不得解析；非法游标 400 `invalid_value`，不是 500。
15. **`GET /activities` 与 `GET /follow_ups` 的排序固定**：活动按 `-activity_at`（第二键 id 倒序），待办按 `due_at` 升序（第二键 id）。不暴露 `sort` 参数——P3 没有第三个消费者，多一个参数就多一个越权/注入面。
16. **P2 债务 #22 的拆包**（`opportunities/service.py` 515 行 → 包）在 Task 1 完成，**只搬代码不改语义**；公共导入路径 `app.modules.opportunities.service` 保持不变（`__init__.py` 重导出）。债务 #23 的两条取证缺口（软删在 `list.total`、公海客户名下机会 `change_stage` → 403）同任务补上。

```python
"""机会读取：可见性、列表、看板、单条。

作用域规则不在这里定义，而是组合 P1 的单一入口：可见机会 = 可见客户名下的机会。
写成 ``Opportunity.customer_id.in_(customer_query(actor).with_only_columns(Customer.id))``
而不是 join，是为了让"可见性只有一个真值源"在代码里一眼可见。
"""

from dataclasses import dataclass
from datetime import date
from decimal import Decimal

from sqlalchemy import ColumnElement, Select, func, or_, select
from sqlalchemy.orm import Session, joinedload

from app.core.errors import ForbiddenError, InvalidValueError, NotFoundError
from app.core.text import LIKE_ESCAPE, contains_pattern
from app.db.scope import customer_query
from app.modules.customers.models import Customer
from app.modules.customers.service import get_customer
from app.modules.opportunities.models import OPPORTUNITY_STAGES, Opportunity
from app.modules.users.models import User

_SORTABLE = {
    "created_at": Opportunity.created_at,
    "updated_at": Opportunity.updated_at,
    "amount": Opportunity.amount,
    "expected_close_date": Opportunity.expected_close_date,
}

# 看板每列最多返回多少条：`total` 是全量聚合（页头显示真实条数），items 只给前 N 条。
BOARD_COLUMN_LIMIT = 200


@dataclass(frozen=True)
class BoardColumn:
    """看板一列：全量聚合 + 前 N 条明细。"""

    stage: str
    total: int
    amount_total: Decimal
    items: list[Opportunity]


def _visible_conditions(
    actor: User, *, customer_id: int | None = None
) -> list[ColumnElement[bool]]:
    """机会可见性的唯一构造点：软删过滤 + 客户作用域（+ 可选的单客户过滤）。"""
    conditions: list[ColumnElement[bool]] = [
        Opportunity.deleted_at.is_(None),
        Opportunity.customer_id.in_(
            customer_query(actor).with_only_columns(Customer.id)
        ),
    ]
    if customer_id is not None:
        conditions.append(Opportunity.customer_id == customer_id)
    return conditions


def _visible_query(actor: User) -> Select:
    return select(Opportunity).where(*_visible_conditions(actor))


def _with_relations(stmt: Select) -> Select:
    """三个关系一律显式预加载（模型上是 lazy="raise"，漏了立刻报错）。"""
    return stmt.options(
        joinedload(Opportunity.customer),
        joinedload(Opportunity.owner),
        joinedload(Opportunity.lost_reason),
    )


def _load_full(db: Session, opportunity_id: int) -> Opportunity:
    """写完回读一次，带上三个关系。返回的对象可直接序列化成 OpportunityRead。"""
    return db.execute(
        _with_relations(select(Opportunity))
        .where(Opportunity.id == opportunity_id)
        .execution_options(populate_existing=True)
    ).scalar_one()


def _validate_filter_stage(stage: str | None) -> None:
    if stage and stage not in OPPORTUNITY_STAGES:
        raise InvalidValueError(f"未知阶段：{stage}")


def get_opportunity(db: Session, actor: User, opportunity_id: int) -> Opportunity:
    """按作用域取单个机会：不存在 404，存在但看不到 403。"""
    opportunity = db.execute(
        _with_relations(_visible_query(actor)).where(Opportunity.id == opportunity_id)
    ).scalar_one_or_none()
    if opportunity is not None:
        return opportunity
    exists = db.execute(
        select(Opportunity.id).where(
            Opportunity.id == opportunity_id, Opportunity.deleted_at.is_(None)
        )
    ).scalar_one_or_none()
    if exists is None:
        raise NotFoundError("机会不存在")
    raise ForbiddenError("无权查看该机会")


def list_opportunities(
    db: Session,
    actor: User,
    *,
    keyword: str | None = None,
    stage: str | None = None,
    customer_id: int | None = None,
    owner_id: int | None = None,
    date_from: date | None = None,
    date_to: date | None = None,
    page: int = 1,
    page_size: int = 20,
    sort: str = "-created_at",
) -> tuple[list[Opportunity], int]:
    """作用域内的机会分页（参数语义见 P2 计划与 spec §5）。"""
    _validate_filter_stage(stage)
    if date_from is not None and date_to is not None and date_from > date_to:
        raise InvalidValueError("开始日期不能晚于结束日期")
    if customer_id is not None:
        get_customer(db, actor, customer_id)

    stmt = select(Opportunity).where(
        *_visible_conditions(actor, customer_id=customer_id)
    )
    if keyword and keyword.strip():
        pattern = contains_pattern(keyword.strip())
        stmt = stmt.where(
            or_(
                Opportunity.name.ilike(pattern, escape=LIKE_ESCAPE),
                Opportunity.competitor.ilike(pattern, escape=LIKE_ESCAPE),
                Opportunity.customer_id.in_(
                    customer_query(actor)
                    .with_only_columns(Customer.id)
                    .where(Customer.name.ilike(pattern, escape=LIKE_ESCAPE))
                ),
            )
        )
    if stage:
        stmt = stmt.where(Opportunity.stage == stage)
    if owner_id is not None:
        stmt = stmt.where(Opportunity.owner_id == owner_id)
    if date_from is not None:
        stmt = stmt.where(Opportunity.expected_close_date >= date_from)
    if date_to is not None:
        stmt = stmt.where(Opportunity.expected_close_date <= date_to)

    total = db.execute(select(func.count()).select_from(stmt.subquery())).scalar_one()

    stmt = _with_relations(stmt)
    normalized = sort.strip() or "-created_at"
    descending = normalized.startswith("-")
    field = normalized.lstrip("-")
    column = _SORTABLE.get(field)
    if column is None:
        raise InvalidValueError(f"不支持的排序字段：{field}")
    stmt = stmt.order_by(
        column.desc() if descending else column.asc(), Opportunity.id
    )
    stmt = stmt.offset((page - 1) * page_size).limit(page_size)
    return list(db.execute(stmt).scalars().all()), int(total)


def board(
    db: Session, actor: User, *, customer_id: int | None = None
) -> list[BoardColumn]:
    """看板数据：固定六列，每列全量聚合 + 前 ``BOARD_COLUMN_LIMIT`` 条明细。"""
    if customer_id is not None:
        get_customer(db, actor, customer_id)
    conditions = _visible_conditions(actor, customer_id=customer_id)

    stats = {
        stage: (int(total), Decimal(amount_total))
        for stage, total, amount_total in db.execute(
            select(
                Opportunity.stage,
                func.count(),
                func.coalesce(func.sum(Opportunity.amount), 0),
            )
            .where(*conditions)
            .group_by(Opportunity.stage)
        ).all()
    }

    columns: list[BoardColumn] = []
    for stage in OPPORTUNITY_STAGES:
        total, amount_total = stats.get(stage, (0, Decimal(0)))
        if total == 0:
            columns.append(
                BoardColumn(stage=stage, total=0, amount_total=Decimal(0), items=[])
            )
            continue
        items = list(
            db.execute(
                _with_relations(select(Opportunity).where(*conditions))
                .where(Opportunity.stage == stage)
                .order_by(
                    Opportunity.expected_close_date.asc().nulls_last(),
                    Opportunity.id,
                )
                .limit(BOARD_COLUMN_LIMIT)
            )
            .scalars()
            .all()
        )
        columns.append(
            BoardColumn(
                stage=stage, total=total, amount_total=amount_total, items=items
            )
        )
    return columns
```

```python
# 库里的 NOT NULL 列：显式传 null 不能落库，按取值非法（400）而不是撞 500
_REQUIRED_FIELDS = {"name": "机会名称", "amount": "预计金额"}

# update 认的字段，与 schemas.OpportunityUpdate 一一对应（字面量白名单，理由见 P2 计划）
UPDATABLE_FIELDS = frozenset(
    {"name", "amount", "expected_close_date", "competitor", "win_rate"}

def _clean_name(name: str | None) -> str:
    cleaned = (name or "").strip()
    if not cleaned:
        raise InvalidValueError("机会名称不能为空")
    return cleaned


def _clean_optional(value: str | None) -> str | None:
    if value is None:
        return None
    cleaned = value.strip()
    return cleaned or None


def _validate_stage_for_create(stage: str) -> None:
    if stage not in OPPORTUNITY_STAGES:
        raise InvalidValueError(f"未知阶段：{stage}")
    if stage in TERMINAL_STAGES:
        raise InvalidValueError(
            "新建机会只能从推进阶段开始；赢单/输单必须通过阶段变更产生"
        )


def _writable_customer(db: Session, actor: User, customer_id: int) -> Customer:
    """写入前必经：先按作用域取客户（403/404 分开），再判可写（公海只读）。"""
    customer = get_customer(db, actor, customer_id)
    assert_customer_writable(customer, actor)
    return customer


def create_opportunity(
    db: Session, actor: User, payload: OpportunityCreate
) -> Opportunity:
    name = _clean_name(payload.name)
    _validate_stage_for_create(payload.stage)
    customer = _writable_customer(db, actor, payload.customer_id)
    if customer.owner_id is None:
        raise InvalidValueError("客户未分配负责人，请先领取或分配后再新建机会")

    opportunity = Opportunity(
        customer_id=customer.id,
        name=name,
        stage=payload.stage,
        amount=payload.amount,
        expected_close_date=payload.expected_close_date,
        competitor=_clean_optional(payload.competitor),
        owner_id=customer.owner_id,
        win_rate=payload.win_rate,
        created_by=actor.id,
    )
    db.add(opportunity)
    db.flush()  # 拿到自增 id，history 需要它
    db.add(
        StageHistory(
            opportunity_id=opportunity.id,
            from_stage=None,
            to_stage=opportunity.stage,
            amount_snapshot=opportunity.amount,
            note=None,
            operator_id=actor.id,
        )
    )
    db.commit()
    return _load_full(db, opportunity.id)


def update_opportunity(
    db: Session, actor: User, opportunity_id: int, payload: OpportunityUpdate
) -> Opportunity:
    opportunity = get_opportunity(db, actor, opportunity_id)
    _writable_customer(db, actor, opportunity.customer_id)

    changes = payload.model_dump(exclude_unset=True)
    unknown = set(changes) - UPDATABLE_FIELDS
    if unknown:
        raise InvalidValueError(f"不可更新的字段：{'、'.join(sorted(unknown))}")
    for field, label in _REQUIRED_FIELDS.items():
        if field in changes and changes[field] is None:
            raise InvalidValueError(f"{label}不能为空")
    if "name" in changes:
        changes["name"] = _clean_name(changes["name"])
    if "competitor" in changes:
        changes["competitor"] = _clean_optional(changes["competitor"])
    for field, value in changes.items():
        setattr(opportunity, field, value)
    db.commit()
    return _load_full(db, opportunity.id)


def delete_opportunity(db: Session, actor: User, opportunity_id: int) -> None:
    if actor.role not in (ROLE_ADMIN, ROLE_MANAGER):
        raise ForbiddenError("仅主管及以上可删除机会")
    opportunity = get_opportunity(db, actor, opportunity_id)
    _writable_customer(db, actor, opportunity.customer_id)
    opportunity.deleted_at = datetime.now(UTC)
    db.commit()


def sync_opportunity_owner(db: Session, *, customer_id: int, owner_id: int) -> int:
    """把某客户名下**未关闭**机会的负责人改到新负责人。返回实际受影响行数。"""
    result = db.execute(
        update(Opportunity)
        .where(
            Opportunity.customer_id == customer_id,
            Opportunity.deleted_at.is_(None),
            Opportunity.stage.not_in(TERMINAL_STAGES),
            Opportunity.owner_id.is_distinct_from(owner_id),
        )
        .values(owner_id=owner_id)
    )
    return int(result.rowcount or 0)
```

```python
"""机会阶段变更：唯一入口，同事务写 stage_histories。

规则全部来自 design §3.6（终态互转、重开权限与原因、输单原因、won_at、手工赢单率、
不碰 customers.last_activity_at），逐条落在 change_stage 里。
"""

from datetime import UTC, datetime

from sqlalchemy.orm import Session

from app.core.errors import ForbiddenError, InvalidValueError
from app.modules.lost_reasons.service import get_lost_reason
from app.modules.opportunities.models import (
    OPPORTUNITY_STAGES,
    TERMINAL_STAGES,
    Opportunity,
    StageHistory,
)
from app.modules.opportunities.schemas import StageChange
from app.modules.opportunities.service.reads import _load_full, get_opportunity
from app.modules.opportunities.service.writes import _clean_optional, _writable_customer

# 重开已关闭的机会限这两个角色（design §3.6 + P2 裁定第 10 条）
_REOPEN_ROLES = (ROLE_ADMIN, ROLE_MANAGER)


def _validate_target_stage(stage: str) -> None:
    if stage not in OPPORTUNITY_STAGES:
        raise InvalidValueError(f"未知阶段：{stage}")


def change_stage(
    db: Session, actor: User, opportunity_id: int, payload: StageChange
) -> Opportunity:
    _validate_target_stage(payload.stage)
    opportunity = get_opportunity(db, actor, opportunity_id)
    _writable_customer(db, actor, opportunity.customer_id)

    if opportunity.stage == payload.stage:
        raise InvalidValueError("机会已处于该阶段")
    note = (payload.note or "").strip() or None

    was_closed = opportunity.stage in TERMINAL_STAGES
    if was_closed:
        if payload.stage in TERMINAL_STAGES:
            raise InvalidValueError(
                "已关闭的机会不能直接改为另一个终态，请先重开到推进阶段"
            )
        if actor.role not in _REOPEN_ROLES:
            raise ForbiddenError("仅主管及以上可重开已关闭的机会")
        if note is None:
            raise InvalidValueError("重开机会必须填写重开原因")

    if payload.stage == "lost":
        if payload.lost_reason_id is None:
            raise InvalidValueError("输单必须选择输单原因")
        reason = get_lost_reason(db, payload.lost_reason_id)
        if not reason.active:
            raise InvalidValueError("该输单原因已停用，请选择其他原因")
    elif payload.lost_reason_id is not None or payload.lost_note is not None:
        raise InvalidValueError("只有输单阶段可以填写输单原因与输单备注")

    if payload.stage == "won":
        opportunity.won_at = datetime.now(UTC)
        opportunity.lost_reason_id = None
        opportunity.lost_note = None
    elif payload.stage == "lost":
        opportunity.won_at = None
        opportunity.lost_reason_id = payload.lost_reason_id
        opportunity.lost_note = _clean_optional(payload.lost_note)
    else:
        opportunity.won_at = None
        opportunity.lost_reason_id = None
        opportunity.lost_note = None

    history = StageHistory(
        opportunity_id=opportunity.id,
        from_stage=opportunity.stage,   # 必须在改 stage 之前取
        to_stage=payload.stage,
        amount_snapshot=opportunity.amount,
        note=note,
        operator_id=actor.id,
    )
    opportunity.stage = payload.stage
    db.add(history)
    db.commit()
    return _load_full(db, opportunity.id)
```

```python
"""业务时区（Asia/Shanghai）的日界换算。

数据库与接口一律 UTC（spec §5），但「今天」「逾期」是业务概念，必须按上海时区
划天。这里只提供两个函数，避免每个模块各写一遍 ``datetime(y, m, d, tzinfo=...)``——
写错一处就会把凌晨 0–8 点的记录算到前一天。
"""

from datetime import UTC, date, datetime, timedelta
from zoneinfo import ZoneInfo

SHANGHAI = ZoneInfo("Asia/Shanghai")


def day_start(day: date) -> datetime:
    """把日期解释成 Asia/Shanghai 当天 00:00（带偏移的 aware datetime）。"""
    return datetime(day.year, day.month, day.day, tzinfo=SHANGHAI)


def day_bounds(day: date) -> tuple[datetime, datetime]:
    """``[当天 00:00, 次日 00:00)`` 半开区间：右端用半开区间才不会漏掉当天下午。"""
    start = day_start(day)
    return start, start + timedelta(days=1)


def today_bounds(now: datetime | None = None) -> tuple[datetime, datetime]:
    """「现在」所在的上海时区自然日的 ``[00:00, 次日 00:00)``。"""
    local = (now or datetime.now(UTC)).astimezone(SHANGHAI)
    return day_bounds(local.date())
```

```python
"""跟进记录服务。

可见性完全继承客户（与 contacts 同口径）：读取先 ``get_customer``（403/404 分开），
列表用 ``customer_query(actor)`` 的子查询表达可见客户集合，本模块不自拼作用域。
写入侧的「写一条跟进顺带建待办」「完成待办顺带写跟进」的事务边界见 create_activity
与 followups.service.complete_follow_up。
"""

from datetime import date

from sqlalchemy import ColumnElement, Select, func, select
from sqlalchemy.orm import Session, joinedload

from app.core.errors import ForbiddenError, InvalidValueError, NotFoundError
from app.core.timeutil import day_bounds
from app.db.scope import customer_query
from app.modules.activities.models import ACTIVITY_TYPES, Activity
from app.modules.customers.models import Customer
from app.modules.customers.service import get_customer
from app.modules.users.models import User


def _visible_conditions(
    actor: User, *, customer_id: int | None = None
) -> list[ColumnElement[bool]]:
    """跟进可见性的唯一构造点：软删过滤 + 客户作用域（+ 可选的单客户过滤）。"""
    conditions: list[ColumnElement[bool]] = [
        Activity.deleted_at.is_(None),
        Activity.customer_id.in_(
            customer_query(actor).with_only_columns(Customer.id)
        ),
    ]
    if customer_id is not None:
        conditions.append(Activity.customer_id == customer_id)
    return conditions


def _with_relations(stmt: Select) -> Select:
    """列表与详情只预加载操作人：联系人/机会姓名只有时间线才需要。"""
    return stmt.options(joinedload(Activity.operator))


def get_activity(db: Session, actor: User, activity_id: int) -> Activity:
    """按作用域取单条跟进：不存在 404，存在但看不到 403。"""
    activity = db.execute(
        _with_relations(select(Activity)).where(
            *_visible_conditions(actor), Activity.id == activity_id
        )
    ).scalar_one_or_none()
    if activity is not None:
        return activity
    exists = db.execute(
        select(Activity.id).where(
            Activity.id == activity_id, Activity.deleted_at.is_(None)
        )
    ).scalar_one_or_none()
    if exists is None:
        raise NotFoundError("跟进记录不存在")
    raise ForbiddenError("无权查看该跟进记录")


def _validate_type(value: str | None, label: str = "跟进方式") -> None:
    """枚举取值非法是 400（不是空列表）：空列表会把"参数拼错"显示成"没有数据"。"""
    if value is not None and value not in ACTIVITY_TYPES:
        raise InvalidValueError(f"未知{label}：{value}")


def list_activities(
    db: Session,
    actor: User,
    *,
    customer_id: int | None = None,
    type: str | None = None,
    created_by: int | None = None,
    date_from: date | None = None,
    date_to: date | None = None,
    page: int = 1,
    page_size: int = 20,
) -> tuple[list[Activity], int]:
    """作用域内的跟进分页，按 `activity_at` 倒序（第二键 id 倒序，翻页稳定）。"""
    _validate_type(type)
    if date_from is not None and date_to is not None and date_from > date_to:
        raise InvalidValueError("开始日期不能晚于结束日期")
    if customer_id is not None:
        # 筛一个看不见的客户应当 403，而不是返回空列表（同 P2 机会列表）
        get_customer(db, actor, customer_id)

    stmt = select(Activity).where(
        *_visible_conditions(actor, customer_id=customer_id)
    )
    if type:
        stmt = stmt.where(Activity.type == type)
    if created_by is not None:
        stmt = stmt.where(Activity.created_by == created_by)
    if date_from is not None:
        stmt = stmt.where(Activity.activity_at >= day_bounds(date_from)[0])
    if date_to is not None:
        stmt = stmt.where(Activity.activity_at < day_bounds(date_to)[1])

    total = db.execute(select(func.count()).select_from(stmt.subquery())).scalar_one()

    stmt = _with_relations(stmt).order_by(
        Activity.activity_at.desc(), Activity.id.desc()
    )
    stmt = stmt.offset((page - 1) * page_size).limit(page_size)
    return list(db.execute(stmt).scalars().all()), int(total)
```

```python
"""待办（design §3.9）。

**不设负责人字段**：待办跟着客户走，客户转给谁，待办就归谁。两个真值源（客户负责人
+ 待办负责人）一定会打架，查询"我的今日待办"即 join customers 后按
`customers.owner_id = me` 过滤。

`done_at` 与 `status` 的一致性由 CHECK 兜底（`status='done'` 必须有 `done_at`）：
绕过 service 的写入（运维 SQL、将来的导入）也不能留下"已完成但没有完成时间"的行，
否则 P5 的跟进量/及时率报表会算不出周期。
"""

from datetime import datetime
from typing import TYPE_CHECKING

from sqlalchemy import (
    BigInteger,
    CheckConstraint,
    DateTime,
    ForeignKey,
    Index,
    String,
    Text,
    text,
)
from sqlalchemy.orm import Mapped, mapped_column, relationship

from app.db.base import Base, SoftDeleteMixin, TimestampMixin

if TYPE_CHECKING:
    from app.modules.activities.models import Activity  # noqa: F401
    from app.modules.contacts.models import Contact
    from app.modules.customers.models import Customer
    from app.modules.opportunities.models import Opportunity
    from app.modules.users.models import User

# design §3.9：pending / done / cancelled
FOLLOW_UP_STATUSES = ("pending", "done", "cancelled")

_STATUS_SQL = "(" + ", ".join(f"'{value}'" for value in FOLLOW_UP_STATUSES) + ")"


class FollowUp(Base, TimestampMixin, SoftDeleteMixin):
    __tablename__ = "follow_ups"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    customer_id: Mapped[int] = mapped_column(
        BigInteger, ForeignKey("customers.id"), nullable=False
    )
    contact_id: Mapped[int | None] = mapped_column(
        BigInteger, ForeignKey("contacts.id"), nullable=True
    )
    opportunity_id: Mapped[int | None] = mapped_column(
        BigInteger, ForeignKey("opportunities.id"), nullable=True
    )
    # 含时分：首页「今日待办」按上海时区自然日切分，只到日期会丢掉"下午三点前回电"
    due_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False
    )
    content: Mapped[str] = mapped_column(Text, nullable=False)
    status: Mapped[str] = mapped_column(
        String(16), nullable=False, default="pending", server_default="pending"
    )
    done_at: Mapped[datetime | None] = mapped_column(
        DateTime(timezone=True), nullable=True
    )
    created_by: Mapped[int] = mapped_column(
        BigInteger, ForeignKey("users.id"), nullable=False
    )

    customer: Mapped["Customer"] = relationship("Customer", lazy="raise")
    contact: Mapped["Contact | None"] = relationship("Contact", lazy="raise")
    opportunity: Mapped["Opportunity | None"] = relationship(
        "Opportunity", lazy="raise"
    )
    operator: Mapped["User"] = relationship(
        "User", foreign_keys=[created_by], lazy="raise"
    )

    __table_args__ = (
        Index("ix_follow_ups_status_due_at", "status", "due_at"),
        Index(
            "ix_follow_ups_customer_id_status_due_at",
            "customer_id",
            "status",
            "due_at",
        ),
        CheckConstraint(f"status IN {_STATUS_SQL}", name="status"),
        # done 必须有完成时间；未完成的行不允许有完成时间（复活后必须清干净）
        CheckConstraint(
            "(status = 'done') = (done_at IS NOT NULL)", name="done_at_consistency"
        ),
    )
```

```python
"""待办服务。

可见性完全继承客户（裁定 3）：读取先 ``get_customer``（403/404 分开），列表用
``customer_query(actor)`` 的子查询表达可见客户集合。
「我的待办」= 在可见集合再收窄到 ``customers.owner_id = actor.id``（spec §3.9），
**不是**按 ``follow_ups.created_by``——后者会让接手人看不到前任留下的待办。
"""

from sqlalchemy import ColumnElement, Select, func, select
from sqlalchemy.orm import Session, joinedload

from app.core.errors import ForbiddenError, InvalidValueError, NotFoundError
from app.db.scope import customer_query
from app.modules.customers.models import Customer
from app.modules.customers.service import get_customer
from app.modules.followups.models import FOLLOW_UP_STATUSES, FollowUp
from app.modules.users.models import User


def _visible_conditions(
    actor: User, *, customer_id: int | None = None, mine: bool = False
) -> list[ColumnElement[bool]]:
    """待办可见性的唯一构造点：软删过滤 + 客户作用域（+ 单客户 / 只看自己）。"""
    visible_customers = customer_query(actor).with_only_columns(Customer.id)
    if mine:
        visible_customers = visible_customers.where(Customer.owner_id == actor.id)
    conditions: list[ColumnElement[bool]] = [
        FollowUp.deleted_at.is_(None),
        FollowUp.customer_id.in_(visible_customers),
    ]
    if customer_id is not None:
        conditions.append(FollowUp.customer_id == customer_id)
    return conditions


def _with_relations(stmt: Select) -> Select:
    """客户名与创建人姓名随列表返回，两条 LEFT JOIN，不退化成逐条回查。"""
    return stmt.options(
        joinedload(FollowUp.customer), joinedload(FollowUp.operator)
    )


def validate_status(value: str | None) -> None:
    """枚举取值非法是 400；空串按"未筛选"处理（前端清空下拉时会带 ``?status=``）。"""
    if value and value not in FOLLOW_UP_STATUSES:
        raise InvalidValueError(f"未知待办状态：{value}")


def get_follow_up(db: Session, actor: User, follow_up_id: int) -> FollowUp:
    """按作用域取单条待办：不存在 404，存在但看不到 403。"""
    follow_up = db.execute(
        _with_relations(select(FollowUp)).where(
            *_visible_conditions(actor), FollowUp.id == follow_up_id
        )
    ).scalar_one_or_none()
    if follow_up is not None:
        return follow_up
    exists = db.execute(
        select(FollowUp.id).where(
            FollowUp.id == follow_up_id, FollowUp.deleted_at.is_(None)
        )
    ).scalar_one_or_none()
    if exists is None:
        raise NotFoundError("待办不存在")
    raise ForbiddenError("无权查看该待办")


def list_follow_ups(
    db: Session,
    actor: User,
    *,
    customer_id: int | None = None,
    status: str | None = None,
    mine: bool = False,
    page: int = 1,
    page_size: int = 20,
) -> tuple[list[FollowUp], int]:
    """作用域内的待办分页，按 `due_at` 升序（第二键 id，翻页稳定）。"""
    validate_status(status)
    if customer_id is not None:
        get_customer(db, actor, customer_id)

    stmt = select(FollowUp).where(
        *_visible_conditions(actor, customer_id=customer_id, mine=mine)
    )
    if status:
        stmt = stmt.where(FollowUp.status == status)

    total = db.execute(select(func.count()).select_from(stmt.subquery())).scalar_one()

    stmt = _with_relations(stmt).order_by(FollowUp.due_at.asc(), FollowUp.id.asc())
    stmt = stmt.offset((page - 1) * page_size).limit(page_size)
    return list(db.execute(stmt).scalars().all()), int(total)
```

```python
def mark_customer_activity(
    db: Session, *, customer_id: int, occurred_at: datetime
) -> None:
    """把客户的「最后有效跟进时间」推进到 ``occurred_at``（不 commit）。

    design §3.3 的三个同步点只有「新建 activity」「领取」「转移」；P4 之前只有第一个
    有调用方。**用 ``GREATEST`` 而不是直接赋值**：补录历史跟进时不能把时间倒回去，
    否则一个 40 天没跟进的客户会因为补录了一条半年前的记录而"变新鲜"，回收任务永远
    收不到它。

    本函数不 commit：调用方（写跟进、完成待办顺带写跟进）必须与业务行落在同一个
    事务里，否则会出现"跟进已入库、客户仍被视为僵尸"的中间态。
    """
    value = literal(occurred_at, type_=DateTime(timezone=True))
    db.execute(
        update(Customer)
        .where(Customer.id == customer_id)
        .values(
            last_activity_at=func.greatest(
                func.coalesce(Customer.last_activity_at, value), value
            )
        )
    )
```

```python
def _clean_content(content: str | None) -> str:
    """strip 后不能为空：全空格能通过 schema 的 ``min_length=1``，却是一行看不见的空白。"""
    cleaned = (content or "").strip()
    if not cleaned:
        raise InvalidValueError("待办内容不能为空")
    return cleaned


def create_pending_follow_up_in_tx(
    db: Session,
    *,
    customer_id: int,
    contact_id: int | None,
    opportunity_id: int | None,
    due_at: datetime,
    content: str,
    created_by: int,
) -> FollowUp:
    """插一条 pending 待办，**不 commit**。

    两个调用方：``POST /follow_ups``（Task 5）与「写跟进时填了下次跟进」
    （activities.create_activity）。后者是跨模块调用，因此这里不校验权限、不 commit
    ——权限与事务由调用方负责，重复校验会让"谁能写待办"出现两个口径。
    """
    follow_up = FollowUp(
        customer_id=customer_id,
        contact_id=contact_id,
        opportunity_id=opportunity_id,
        due_at=due_at,
        content=_clean_content(content),
        status="pending",
        created_by=created_by,
    )
    db.add(follow_up)
    db.flush()  # 拿到自增 id，调用方要在同一响应里返回它
    return follow_up
```

```python
    """完成待办的结果：待办自身 + 可选的随附跟进。"""

    follow_up: FollowUp
    activity: Activity | None


def _load_full(db: Session, follow_up_id: int) -> FollowUp:
    """写完回读：`customer` / `operator` 都是 lazy="raise"。"""
    return db.execute(
        _with_relations(select(FollowUp))
        .where(FollowUp.id == follow_up_id)
        .execution_options(populate_existing=True)

def _assert_can_edit_follow_up(
    follow_up: FollowUp, actor: User, customer: Customer

    """裁定 5 + 9：本人（创建者或客户当前负责人）与管理员可改。"""
    if (
        actor.role == ROLE_ADMIN
        or follow_up.created_by == actor.id
        or customer.owner_id == actor.id
    ):

def _assert_can_delete_follow_up(
    follow_up: FollowUp, actor: User, customer: Customer
) -> None:
    """裁定 5：本人可删；主管可删本部门；管理员全部。"""
    if (
        actor.role == ROLE_MANAGER
        and actor.department_id is not None
        and customer.department_id == actor.department_id
    ):
        return
    _assert_can_edit_follow_up(follow_up, actor, customer)


def create_follow_up(
    db: Session, actor: User, payload: FollowUpCreate
) -> FollowUp:
    customer = get_customer(db, actor, payload.customer_id)
    assert_customer_writable(customer, actor)
    validate_child_links(

        content=payload.content,
        created_by=actor.id,
    )
    db.commit()
    return _load_full(db, follow_up.id)


def update_follow_up(
    db: Session, actor: User, follow_up_id: int, payload: FollowUpUpdate
) -> FollowUp:
    """编辑待办：改内容/到期时间，或在 pending ↔ cancelled 之间切换。"""
    follow_up = get_follow_up(db, actor, follow_up_id)
    customer = get_customer(db, actor, follow_up.customer_id)
    assert_customer_writable(customer, actor)
    _assert_can_edit_follow_up(follow_up, actor, customer)

    changes = payload.model_dump(exclude_unset=True)
    if "status" in changes:
        status = changes["status"]
        if status is None:
            raise InvalidValueError("待办状态不能为空")
        if status == "done":
            raise InvalidValueError("标记完成请使用 POST /follow_ups/{id}/done")
        if status not in ("pending", "cancelled"):
            raise InvalidValueError(f"未知待办状态：{status}")
        if follow_up.status == "done":
            raise InvalidValueError("已完成的待办不能再改状态")
    if "due_at" in changes and changes["due_at"] is None:
        raise InvalidValueError("到期时间不能为空")
    if "content" in changes:
        changes["content"] = _clean_content(changes["content"])
    for field, value in changes.items():
        setattr(follow_up, field, value)
    db.commit()
    return _load_full(db, follow_up.id)


def complete_follow_up(
    db: Session, actor: User, follow_up_id: int, payload: FollowUpDone
) -> Completion:
    """完成待办；可选在同一事务里写一条跟进并刷新 last_activity_at（spec §4.5）。"""
    follow_up = get_follow_up(db, actor, follow_up_id)
    customer = get_customer(db, actor, follow_up.customer_id)
    assert_customer_writable(customer, actor)

    if follow_up.status == "done":
        raise InvalidValueError("该待办已完成")
    if follow_up.status == "cancelled":
        raise InvalidValueError("该待办已取消，不能标记完成")
    if "activity_type" in payload.model_fields_set and not payload.create_activity:
        raise InvalidValueError("未勾选写跟进时不需要指定跟进方式")
    if payload.create_activity:
        validate_activity_type(payload.activity_type)

    now = datetime.now(UTC)
    follow_up.status = "done"
    follow_up.done_at = now

    activity: Activity | None = None
    if payload.create_activity:
        activity = create_activity_record(
            db,
            customer_id=follow_up.customer_id,
            contact_id=follow_up.contact_id,
            opportunity_id=follow_up.opportunity_id,
            type=payload.activity_type,
            content=follow_up.content,
            activity_at=now,
            operator_id=actor.id,
        )

    db.commit()
    return Completion(
        follow_up=_load_full(db, follow_up.id),
        activity=(
            db.execute(
                select(Activity).options(joinedload(Activity.operator)).where(
                    Activity.id == activity.id
                ).execution_options(populate_existing=True)
            ).scalar_one()
            if activity is not None
            else None
        ),
    )


def delete_follow_up(db: Session, actor: User, follow_up_id: int) -> None:

    assert_customer_writable(customer, actor)
    _assert_can_delete_follow_up(follow_up, actor, customer)
    follow_up.deleted_at = datetime.now(UTC)
    db.commit()
```

```python
"""时间线的线上契约。

`type` 现在只会是 `activity` / `stage_change`，但 `owner_change` **预留**在枚举里
（裁定 6）：P4 建 `owner_change_logs` 后接入这一路，前端契约不变、不需要再改类型。

from datetime import datetime
from decimal import Decimal
from typing import Literal

from pydantic import BaseModel, ConfigDict


class TimelineItemRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    type: Literal["activity", "stage_change", "owner_change"]
    id: int
    occurred_at: datetime

    # 操作人：账号停用后姓名仍在，配 operator_disabled 让前端标注"已停用"
    operator_id: int | None
    operator_name: str
    operator_disabled: bool

    # 活动字段（type == "activity" 时有值）
    activity_type: str | None
    content: str | None
    contact_id: int | None
    contact_name: str | None
    contact_deleted: bool

    # 机会与阶段字段（type == "stage_change" 时有值；活动也可能关联机会）
    opportunity_id: int | None
    opportunity_name: str | None
    opportunity_deleted: bool
    from_stage: str | None
    to_stage: str | None
    # 时点金额（裁定 4）：numeric(14,2) 在线上仍是定点字符串
    amount_snapshot: Decimal | None


class TimelinePageRead(BaseModel):
    items: list[TimelineItemRead]
    # 没有更多时为 null；客户端不得解析游标（裁定 14）
    next_cursor: str | None
```

- [ ] **Step 5: 写 `timeline/service.py`**

```python
"""客户时间线：把跟进与阶段变更合并成一条倒序流。

三类来源里 P3 只有两类（`owner_change_logs` 属 P4，裁定 6）。合并放在 SQL 里做
（`UNION ALL` 后统一排序 + 游标过滤），而不是各查一页在 Python 里归并——后者在
"一页里全是活动"时会把另一路的数据整段挤掉，翻页出现空洞。

**游标是 `(occurred_at, type, id)`**（spec §5）：同一秒可能有多条，只按时间翻页会
重复或漏；把 type 与 id 一起放进游标，排序键与游标键严格一致，翻页天然不重不漏。

时间线**故意不套软删过滤**（裁定 1）：已删机会的阶段变更、已删联系人的姓名都要
显示并带标记。这里读的是"发生过什么"，不是"现在还能操作什么"。
"""

from base64 import urlsafe_b64decode, urlsafe_b64encode
from dataclasses import dataclass
from datetime import datetime
from decimal import Decimal

from sqlalchemy import String, and_, literal, or_, select
from sqlalchemy.orm import Session, joinedload

from app.core.errors import InvalidValueError
from app.modules.activities.models import Activity
from app.modules.customers.service import get_customer
from app.modules.opportunities.models import Opportunity, StageHistory
from app.modules.users.models import STATUS_ACTIVE, User

# owner_change 预留给 P4（裁定 6）：枚举先占位，P4 只加一路 UNION，不改前端契约
TIMELINE_TYPES = ("activity", "stage_change", "owner_change")
ACTIVITY_TIMELINE_TYPE = "activity"
STAGE_CHANGE_TIMELINE_TYPE = "stage_change"


@dataclass(frozen=True)
class TimelineCursor:
    occurred_at: datetime
    type: str
    id: int


@dataclass(frozen=True)
class TimelineEntry:
    type: str
    id: int
    occurred_at: datetime
    operator_id: int | None
    operator_name: str
    operator_disabled: bool
    activity_type: str | None
    content: str | None
    contact_id: int | None
    contact_name: str | None
    contact_deleted: bool
    opportunity_id: int | None
    opportunity_name: str | None
    opportunity_deleted: bool
    from_stage: str | None
    to_stage: str | None
    amount_snapshot: Decimal | None


def encode_cursor(entry: TimelineEntry) -> str:
    """把排序键编成不透明字符串（客户端不得解析，裁定 14）。"""
    raw = f"{entry.occurred_at.isoformat()}|{entry.type}|{entry.id}"
    return urlsafe_b64encode(raw.encode("utf-8")).decode("ascii")


def decode_cursor(raw: str) -> TimelineCursor:
    """非法游标是 400 而不是 500：伪造/过期的 cursor 只该让客户端从头开始。"""
    try:
        decoded = urlsafe_b64decode(raw.encode("ascii")).decode("utf-8")
        occurred_at_raw, type_raw, id_raw = decoded.split("|")
        if type_raw not in TIMELINE_TYPES:
            raise ValueError(type_raw)
        return TimelineCursor(
            occurred_at=datetime.fromisoformat(occurred_at_raw),
            type=type_raw,
            id=int(id_raw),
        )
    except (ValueError, UnicodeDecodeError) as exc:
        raise InvalidValueError("时间线游标无效，请重新加载") from exc


def _page_rows(
    db: Session, customer_id: int, cursor: TimelineCursor | None, limit: int
) -> list:
    """取一页排序键：UNION ALL 后按 (occurred_at, type, id) 倒序。

    三列都倒序，游标比较才能用同一组排序键（混合升降序需要逐字段拼条件，容易漏分支）。
    """
    activities = select(
        literal(ACTIVITY_TIMELINE_TYPE, type_=String).label("type"),
        Activity.id.label("id"),
        Activity.activity_at.label("occurred_at"),
    ).where(
        Activity.customer_id == customer_id, Activity.deleted_at.is_(None)
    )

    # 注意：这里**不过滤 Opportunity.deleted_at**（裁定 1）
    histories = (
        select(
            literal(STAGE_CHANGE_TIMELINE_TYPE, type_=String).label("type"),
            StageHistory.id.label("id"),
            StageHistory.changed_at.label("occurred_at"),
        )
        .join(Opportunity, Opportunity.id == StageHistory.opportunity_id)
        .where(Opportunity.customer_id == customer_id)
    )

    merged = activities.union_all(histories).subquery()
    stmt = select(merged.c.type, merged.c.id, merged.c.occurred_at)
    if cursor is not None:
        stmt = stmt.where(
            or_(
                merged.c.occurred_at < cursor.occurred_at,
                and_(
                    merged.c.occurred_at == cursor.occurred_at,
                    merged.c.type < cursor.type,
                ),
                and_(
                    merged.c.occurred_at == cursor.occurred_at,
                    merged.c.type == cursor.type,
                    merged.c.id < cursor.id,
                ),
            )
        )
    stmt = stmt.order_by(
        merged.c.occurred_at.desc(), merged.c.type.desc(), merged.c.id.desc()
    ).limit(limit)
    return list(db.execute(stmt).all())


def _assemble(db: Session, rows: list) -> list[TimelineEntry]:
    """按页内的 id 批量取回两张表的行，再按排序顺序装配（3 条查询，无 N+1）。"""
    activity_ids = [row.id for row in rows if row.type == ACTIVITY_TIMELINE_TYPE]
    history_ids = [row.id for row in rows if row.type == STAGE_CHANGE_TIMELINE_TYPE]

    activities: dict[int, Activity] = {}
    if activity_ids:
        for activity in db.execute(
            select(Activity)
            .options(
                joinedload(Activity.operator),
                joinedload(Activity.contact),
                joinedload(Activity.opportunity),
            )
            .where(Activity.id.in_(activity_ids))
        ).scalars():
            activities[activity.id] = activity

    histories: dict[int, StageHistory] = {}
    if history_ids:
        for history in db.execute(
            select(StageHistory)
            .options(
                joinedload(StageHistory.operator),
                joinedload(StageHistory.opportunity),
            )
            .where(StageHistory.id.in_(history_ids))
        ).scalars():
            histories[history.id] = history

    entries: list[TimelineEntry] = []
    for row in rows:
        if row.type == ACTIVITY_TIMELINE_TYPE:
            activity = activities[row.id]
            operator = activity.operator
            contact = activity.contact
            opportunity = activity.opportunity
            entries.append(
                TimelineEntry(
                    type=ACTIVITY_TIMELINE_TYPE,
                    id=activity.id,
                    occurred_at=activity.activity_at,
                    operator_id=activity.created_by,
                    operator_name=operator.display_name if operator else "",
                    operator_disabled=bool(
                        operator is not None and operator.status != STATUS_ACTIVE
                    ),
                    activity_type=activity.type,
                    content=activity.content,
                    contact_id=activity.contact_id,
                    contact_name=contact.name if contact is not None else None,
                    contact_deleted=bool(
                        contact is not None and contact.deleted_at is not None
                    ),
                    opportunity_id=activity.opportunity_id,
                    opportunity_name=opportunity.name if opportunity else None,
                    opportunity_deleted=bool(
                        opportunity is not None and opportunity.deleted_at is not None
                    ),
                    from_stage=None,
                    to_stage=None,
                    amount_snapshot=None,
                )
            )
        else:
            history = histories[row.id]
            operator = history.operator
            opportunity = history.opportunity
            entries.append(
                TimelineEntry(
                    type=STAGE_CHANGE_TIMELINE_TYPE,
                    id=history.id,
                    occurred_at=history.changed_at,
                    operator_id=history.operator_id,
                    operator_name=operator.display_name if operator else "",
                    operator_disabled=bool(
                        operator is not None and operator.status != STATUS_ACTIVE
                    ),
                    activity_type=None,
                    content=history.note,
                    contact_id=None,
                    contact_name=None,
                    contact_deleted=False,
                    opportunity_id=history.opportunity_id,
                    opportunity_name=opportunity.name if opportunity else None,
                    opportunity_deleted=bool(
                        opportunity is not None and opportunity.deleted_at is not None
                    ),
                    from_stage=history.from_stage,
                    to_stage=history.to_stage,
                    amount_snapshot=history.amount_snapshot,
                )
            )
    return entries


def get_timeline(
    db: Session,
    actor: User,
    customer_id: int,
    *,
    cursor: str | None = None,
    limit: int = 20,
) -> tuple[list[TimelineEntry], str | None]:
    """客户可见才返回时间线（403/404 与其它入口同口径）。"""
    get_customer(db, actor, customer_id)
    parsed = decode_cursor(cursor) if cursor else None

    # 多取一条判断是否还有下一页，返回时再截断
    rows = _page_rows(db, customer_id, parsed, limit + 1)
    has_more = len(rows) > limit
    page_rows = rows[:limit]
    entries = _assemble(db, page_rows)
    next_cursor = encode_cursor(entries[-1]) if has_more and entries else None
    return entries, next_cursor
```

```python
"""首页三块的查询。

三块都属于「我的」范围：
- 今日待办 / 已逾期：可见客户再收窄到 `customers.owner_id = me`（裁定 3）；
- 即将进公海：可见客户里处于预警区间的（主管能看到本部门，销售能看到自己的）。

预警**不落表**（spec §4.2）：直接查询是幂等的，落表就要维护"客户被跟进后预警消失"
的状态同步，必然产生脏数据。
"""

from dataclasses import dataclass
from datetime import UTC, datetime, timedelta

from sqlalchemy import select
from sqlalchemy.orm import Session, joinedload

from app.core.timeutil import SHANGHAI, today_bounds
from app.db.scope import customer_query
from app.modules.customers.models import Customer
from app.modules.followups.models import FollowUp
from app.modules.opportunities.models import OPEN_STAGES, Opportunity
from app.modules.pools.rules import NOTICE_THRESHOLD_DAYS
from app.modules.users.models import User

# 每块最多返回多少条：`total` 是全量计数（页面显示真实条数），items 只给前 N 条
HOME_BLOCK_LIMIT = 50


@dataclass(frozen=True)
class HomeSummary:
    today: list[FollowUp]
    today_total: int
    overdue: list[FollowUp]
    overdue_total: int
    pool_notice: list[Customer]
    pool_notice_total: int


def days_since_local(moment: datetime, now: datetime | None = None) -> int:
    """按上海自然日算"已经几天没动静"（不看时分）。"""
    current = (now or datetime.now(UTC)).astimezone(SHANGHAI).date()
    return (current - moment.astimezone(SHANGHAI).date()).days


def _my_customers(actor: User):
    """「我的客户」= 可见客户中 owner_id 是我的（待办跟客户走，spec §3.9）。"""
    return (
        customer_query(actor)
        .with_only_columns(Customer.id)
        .where(Customer.owner_id == actor.id)
    )


def _follow_up_block(
    db: Session, actor: User, *, start: datetime, end: datetime, overdue: bool
) -> tuple[list[FollowUp], int]:
    stmt = select(FollowUp).where(
        FollowUp.deleted_at.is_(None),
        FollowUp.status == "pending",
        FollowUp.customer_id.in_(_my_customers(actor)),
    )
    if overdue:
        stmt = stmt.where(FollowUp.due_at < start)
    else:
        stmt = stmt.where(FollowUp.due_at >= start, FollowUp.due_at < end)

    total = db.execute(
        select(func.count()).select_from(stmt.subquery())
    ).scalar_one()
    items = list(
        db.execute(
            stmt.options(
                joinedload(FollowUp.customer), joinedload(FollowUp.operator)
            ).order_by(FollowUp.due_at.asc(), FollowUp.id.asc()).limit(HOME_BLOCK_LIMIT)
        )
        .scalars()
        .all()
    )
    return items, int(total)


def _pool_notice(
    db: Session, actor: User, *, now: datetime
) -> tuple[list[Customer], int]:
    threshold = now - timedelta(days=NOTICE_THRESHOLD_DAYS)

    # 两条豁免（spec §4.1/§4.2）：有未关闭机会、有 pending 待办
    open_deal_exists = (
        select(Opportunity.id)
        .where(
            Opportunity.customer_id == Customer.id,
            Opportunity.deleted_at.is_(None),
            Opportunity.stage.in_(OPEN_STAGES),
        )
        .exists()
    )
    pending_todo_exists = (
        select(FollowUp.id)
        .where(
            FollowUp.customer_id == Customer.id,
            FollowUp.deleted_at.is_(None),
            FollowUp.status == "pending",
        )
        .exists()
    )

    stmt = customer_query(actor).where(
        Customer.owner_id.is_not(None),
        Customer.status == "active",
        Customer.last_activity_at < threshold,
        ~open_deal_exists,
        ~pending_todo_exists,
    )

    total = db.execute(
        select(func.count()).select_from(stmt.subquery())
    ).scalar_one()
    items = list(
        db.execute(
            stmt.options(joinedload(Customer.owner))
            .order_by(Customer.last_activity_at.asc(), Customer.id.asc())
            .limit(HOME_BLOCK_LIMIT)
        )
        .scalars()
        .all()
    )
    return items, int(total)


def summary(db: Session, actor: User, *, now: datetime | None = None) -> HomeSummary:
    """一次算三块。`now` 只给测试注入，生产走 `datetime.now(UTC)`。"""
    current = now or datetime.now(UTC)
    start, end = today_bounds(current)

    today_items, today_total = _follow_up_block(
        db, actor, start=start, end=end, overdue=False
    )
    overdue_items, overdue_total = _follow_up_block(
        db, actor, start=start, end=end, overdue=True
    )
    pool_items, pool_total = _pool_notice(db, actor, now=current)

    return HomeSummary(
        today=today_items,
        today_total=today_total,
        overdue=overdue_items,
        overdue_total=overdue_total,
        pool_notice=pool_items,
        pool_notice_total=pool_total,
    )
```

```ts
/**
 * 时间显示与输入的唯一换算点。
 *
 * 后端所有时间都是 UTC ISO 串，而"今天/已逾期/09:30 前"这类判断按 Asia/Shanghai
 * 自然日成立（design §2 的时区约定）。若各页面自己 `toLocaleDateString()`，用户
 * 浏览器时区就会混进业务判断——同一条待办在两台机器上显示不同日期。
 */

const SHANGHAI = "Asia/Shanghai";

const dayFormatter = new Intl.DateTimeFormat("en-CA", {
  timeZone: SHANGHAI,
  year: "numeric",
  month: "2-digit",
  day: "2-digit",
});

const clockFormatter = new Intl.DateTimeFormat("en-GB", {
  timeZone: SHANGHAI,
  hour: "2-digit",
  minute: "2-digit",
  // 只要 `hourCycle: "h23"`，**不要**同时写 `hour12`：V8 实测里 `hour12` 存在时
  // `hourCycle` 被忽略（`{hour12:false, hourCycle:"h24"}` 仍出 `00:00`），只有单写
  // `hourCycle` 才真正钉住 00–23；h24 会把午夜格式化成 `24:00`，拼进
  // `datetime-local` 是非法值。
  hourCycle: "h23",
});

function toDate(value: string): Date | null {
  const date = new Date(value);
  return Number.isNaN(date.getTime()) ? null : date;
}

/** `2026-10-31`（上海日期）。 */
export function formatDay(value: string): string {
  const date = toDate(value);
  return date ? dayFormatter.format(date) : "—";
}

/** `09:30`（上海时刻）。 */
export function formatClock(value: string): string {
  const date = toDate(value);
  return date ? clockFormatter.format(date) : "—";
}

/** `2026-10-31 09:30`（上海）。 */
export function formatDateTime(value: string): string {
  const date = toDate(value);
  return date ? `${dayFormatter.format(date)} ${clockFormatter.format(date)}` : "—";
}

/**
 * 转成 `<input type="datetime-local">` 的取值：`2026-10-31T09:30`。
 * 用上海时区的年月日时分拼装，而不是 `date.toISOString().slice(0,16)`——后者是
 * UTC 值，用户在东八区打开会看到早 8 小时的时间。
 */
export function toDateTimeInput(value: string): string {
  const date = toDate(value);
  if (!date) return "";
  return `${dayFormatter.format(date)}T${clockFormatter.format(date)}`;
}

/** `datetime-local` 的输入值 → 后端要的 ISO 串（按东八区解释）。 */
export function fromDateTimeInput(value: string): string {
  const date = new Date(`${value}:00+08:00`);
  return Number.isNaN(date.getTime()) ? value : date.toISOString();
}

/** 新建待办的默认到期时间：上海时区的「明天 09:00」。 */
export function defaultDueInput(): string {
  const today = dayFormatter.format(new Date()); // YYYY-MM-DD（上海）
  const next = new Date(`${today}T00:00:00+08:00`);
  next.setUTCDate(next.getUTCDate() + 1); // 用 UTC 日期推进，避开夏令时/本地时区
  return `${dayFormatter.format(next)}T09:00`;
}
```

```tsx
  draft?: ActivityDraft;
  onClose: () => void;
  onSaved: () => void;
}

export function ActivityFormModal({ customerId, draft, onClose, onSaved }: Props) {
  const queryClient = useQueryClient();
  const editing = draft !== undefined;

  const [type, setType] = useState<ActivityType>(draft?.type ?? "call");
  const [content, setContent] = useState(draft?.content ?? "");
  const [activityAt, setActivityAt] = useState(
    toDateTimeInput(draft?.activity_at ?? new Date().toISOString()),
  );
  const [contactId, setContactId] = useState<string>(
    draft?.contact_id === null || draft?.contact_id === undefined
      ? ""
      : String(draft.contact_id),
  );
  const [opportunityId, setOpportunityId] = useState<string>(
    draft?.opportunity_id === null || draft?.opportunity_id === undefined
      ? ""
      : String(draft.opportunity_id),
  );
  const [nextDue, setNextDue] = useState(defaultDueInput());
  const [nextContent, setNextContent] = useState("");
  const [error, setError] = useState<string | null>(null);
  const [fieldErrors, setFieldErrors] = useState<Record<string, string>>({});

  // 关联对象下拉：客户可见才有数据，客户不可见时这两个查询会 403，直接当作空列表。
  // 机会的 key 比详情页多一段 "options"：详情页只取 50 条，这里要 200 条，共用
  // 同一个 key 会"先跑的那个决定缓存内容"（React Query 只按 key 缓存，不认参数）
  const contacts = useQuery({
    queryKey: ["contacts", customerId],
    queryFn: () => listContacts(customerId),
  });
  const opportunities = useQuery({
    queryKey: ["opportunities", "customer", customerId, "options"],
    queryFn: () => listOpportunities({ customer_id: customerId, page_size: 200 }),
  });

  const save = useMutation({
    mutationFn: async () => {
      const activityAtIso = fromDateTimeInput(activityAt);
      if (editing) {
        // 关联对象不可改：编辑只提交三个可改字段（裁定 11）
        return updateActivity(draft.id, {
          type,
          content: content.trim(),
          activity_at: activityAtIso,
        });
      }
      const wantsTodo = nextContent.trim() !== "";
      return createActivity({
        customer_id: customerId,
        type,
        content: content.trim(),
        activity_at: activityAtIso,
        contact_id: contactId === "" ? null : Number(contactId),
        opportunity_id: opportunityId === "" ? null : Number(opportunityId),
        next_follow_up: wantsTodo
          ? { due_at: fromDateTimeInput(nextDue), content: nextContent.trim() }
          : null,
      });
    },
    onSuccess: async () => {
      // 写跟进会推进 last_activity_at、可能新增待办、必然新增时间线条目：
      // 三个缓存一起失效，首页/详情/时间线不会各自留旧数据。
      await Promise.all([
        queryClient.invalidateQueries({ queryKey: ["timeline", customerId] }),
        queryClient.invalidateQueries({ queryKey: ["follow_ups"] }),
        queryClient.invalidateQueries({ queryKey: ["home"] }),
        queryClient.invalidateQueries({ queryKey: ["customer", customerId] }),
      ]);
      onSaved();
    },
    onError: (err) => setError(errorMessage(err, "保存跟进失败")),
  });

  function submit() {
    const errors: Record<string, string> = {};
    if (content.trim() === "") errors.content = "请填写跟进内容";
    if (activityAt === "") errors.activityAt = "请选择跟进时间";
    if (!editing && nextContent.trim() !== "" && nextDue === "") {
      errors.nextDue = "请选择下次跟进时间";
    }
    setFieldErrors(errors);
    setError(null);
    if (Object.keys(errors).length > 0) return;
    save.mutate();
  }

  const contactOptions = contacts.data ?? [];
  const opportunityOptions = opportunities.data?.items ?? [];

  return (
    <Modal title={editing ? "编辑跟进" : "写跟进"} onClose={onClose}>
      <div className="space-y-3">
        <label className="block space-y-1">
          <span className="text-sm text-slate-600">跟进方式</span>
          <select
            value={type}
            onChange={(event) => setType(event.target.value as ActivityType)}
            className="w-full rounded-md border border-slate-300 px-3 py-2 text-sm"
          >
            {ACTIVITY_TYPE_OPTIONS.map((value) => (
              <option key={value} value={value}>
                {ACTIVITY_TYPE_LABELS[value]}
              </option>
            ))}
          </select>
        </label>

        <label className="block space-y-1">
          <span className="text-sm text-slate-600">跟进时间</span>
          <input
            type="datetime-local"
            value={activityAt}
            onChange={(event) => setActivityAt(event.target.value)}
            className="w-full rounded-md border border-slate-300 px-3 py-2 text-sm"
          />
          {fieldErrors.activityAt ? (
            <span className="text-xs text-red-600">{fieldErrors.activityAt}</span>
          ) : null}
        </label>

        <label className="block space-y-1">
          <span className="text-sm text-slate-600">跟进内容</span>
          <textarea
            rows={4}
            value={content}
            onChange={(event) => setContent(event.target.value)}
            className="w-full rounded-md border border-slate-300 px-3 py-2 text-sm"
            placeholder="例如：电话确认交期，客户要求 11 月 15 日前到货"
          />
          {fieldErrors.content ? (
            <span className="text-xs text-red-600">{fieldErrors.content}</span>
          ) : null}
        </label>

        <div className="grid grid-cols-1 gap-3 sm:grid-cols-2">
          <label className="block space-y-1">
            <span className="text-sm text-slate-600">关联联系人（可选）</span>
            <select
              value={contactId}
              disabled={editing}
              onChange={(event) => setContactId(event.target.value)}
              className="w-full rounded-md border border-slate-300 px-3 py-2 text-sm disabled:bg-slate-100"
            >
              <option value="">不关联</option>
              {contactOptions.map((contact) => (
                <option key={contact.id} value={contact.id}>
                  {contact.name}
                </option>
              ))}
            </select>
          </label>

          <label className="block space-y-1">
            <span className="text-sm text-slate-600">关联机会（可选）</span>

              value={opportunityId}
              disabled={editing}
              onChange={(event) => setOpportunityId(event.target.value)}
```

```tsx
  onEdit: (draft: ActivityDraft) => void;

 * 客户时间线（spec §5 `GET /customers/{id}/timeline`）。
 *
 * 两类条目（跟进 / 阶段变更）由后端合并排序，前端只按 `type` 换渲染：
 * - 已删机会、已删联系人、已停用账号**照常显示**并加后缀标注（P3 裁定 1）。

export function Timeline({ customerId, onEdit }: Props) {

  const queryClient = useQueryClient();
  const [deleteTarget, setDeleteTarget] = useState<number | null>(null);
  const [deleteError, setDeleteError] = useState<string | null>(null);

    queryKey: ["timeline", customerId],
    queryFn: ({ pageParam }) => getTimeline(customerId, pageParam),
    initialPageParam: null as string | null,
    getNextPageParam: (last) => last.next_cursor ?? undefined,
  });

  const remove = useMutation({
    mutationFn: (id: number) => deleteActivity(id),
    onSuccess: async () => {
      setDeleteTarget(null);
      setDeleteError(null);
      await Promise.all([
        queryClient.invalidateQueries({ queryKey: ["timeline", customerId] }),
        queryClient.invalidateQueries({ queryKey: ["home"] }),
      ]);
    },
    onError: (err) => setDeleteError(errorMessage(err, "删除跟进失败")),
  });

  if (timeline.isLoading) return <p className="text-sm text-slate-500">加载中…</p>;

    return (
      <p className="break-words text-sm text-red-600">
        {errorMessage(timeline.error, "时间线加载失败")}
      </p>
    );
  }

          // 部门归属，前端不猜；后端仍会按裁定 5 放行/拒绝。
          const mine = item.operator_id !== null && item.operator_id === user?.id;

                  {item.contact_name ? ` · 联系人 ${item.contact_name}` : ""}
                  {item.contact_deleted ? "（已删除）" : ""}
                  {item.type === "stage_change" && item.opportunity_name
                    ? ` · ${item.opportunity_name}`
                    : ""}
                  {item.opportunity_deleted ? "（已删除）" : ""}
                  {item.type === "stage_change" && item.amount_snapshot

                    : ""}

                    <button
                      type="button"
                      onClick={() =>
                        onEdit({

                          // `activity_type` 对 activity 条目恒非空；兜底 "other" 只为类型收窄
                          type: item.activity_type ?? "other",
                          content: item.content ?? "",
                          activity_at: item.occurred_at,
                          contact_id: item.contact_id,
                          opportunity_id: item.opportunity_id,
                        })
                      }
                      className="text-slate-500 hover:text-brand-600"

                        setDeleteError(null);
                        setDeleteTarget(item.id);

                    </button>
                  </div>
                ) : null}
              </div>
            </li>
          );
        })}
      </ol>

      {timeline.hasNextPage ? (

          type="button"

          onClick={() => void timeline.fetchNextPage()}
          className="rounded-md border border-slate-300 px-3 py-1.5 text-sm hover:bg-slate-100 disabled:opacity-60"

            </div>
```

```python
    timeline 合并四处各自单测都绿，但"待办完成后首页消失、时间线多一条"只有连起来
    跑才成立。
    """
    from datetime import timedelta

    from app.modules.customers.schemas import CustomerCreate
    from app.modules.customers.service import create_customer
    from app.modules.departments.service import create_department
    from app.modules.users.models import ROLE_ADMIN, ROLE_SALES
    from app.modules.users.service import create_user

    department = create_department(db, "P3 验收部")
    admin = create_user(
        db, username="p3_admin", password="Passw0rd!", display_name="P3 管理员",
        role=ROLE_ADMIN, department_id=None,
    )
    sales = create_user(
        db, username="p3_sales", password="Passw0rd!", display_name="P3 销售",
        role=ROLE_SALES, department_id=department.id,
    )
    customer = create_customer(db, sales, CustomerCreate(name="P3 验收客户有限公司"))
    headers = _auth(client, "p3_sales")

    # 1) 写跟进 + 顺手排一条待办
    created = client.post(
        "/api/v1/activities",
        headers=headers,
        json={
            "customer_id": customer.id,
            "type": "call",
            "content": "确认技术参数",
            "next_follow_up": {
                "due_at": (datetime.now(UTC) + timedelta(days=1)).isoformat(),
                "content": "寄样册",
            },
        },
    )
    assert created.status_code == 201, created.text
    activity_id = created.json()["id"]

    # 2) 首页「今日待办」看不到（明天到期），但「我的待办」列表有它
    home = client.get("/api/v1/home", headers=headers)
    assert home.status_code == 200, home.text
    today_ids = [item["id"] for item in home.json()["today"]["items"]]
    todos = client.get("/api/v1/follow_ups?mine=true", headers=headers).json()
    todo_id = todos["items"][0]["id"]
    assert todo_id not in today_ids

    # 3) 完成待办并顺便写跟进
    done = client.post(
        f"/api/v1/follow_ups/{todo_id}/done",
        headers=headers,
        json={"create_activity": True, "activity_type": "visit"},
    )
    assert done.status_code == 200, done.text
    assert done.json()["activity"]["content"] == "寄样册"
    assert done.json()["follow_up"]["status"] == "done"

    # 4) 首页不再显示它
    home_after = client.get("/api/v1/home", headers=headers).json()
    assert todo_id not in [item["id"] for item in home_after["overdue"]["items"]]
    assert todo_id not in [item["id"] for item in home_after["today"]["items"]]

    # 5) 时间线两条（原始跟进 + 完成待办产生的跟进），且客户新鲜度已推进
    timeline = client.get(
        f"/api/v1/customers/{customer.id}/timeline", headers=headers
    ).json()
    contents = [item["content"] for item in timeline["items"] if item["type"] == "activity"]
    assert contents == ["寄样册", "确认技术参数"]

    detail = client.get(f"/api/v1/customers/{customer.id}", headers=headers).json()
    assert detail["last_activity_at"] is not None
    assert activity_id is not None
    assert admin.id is not None
```
