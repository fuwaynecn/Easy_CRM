## 1. 本机环境速查

| 组件 | 值 | 本机特有的坑 |
|---|---|---|
| PostgreSQL | 便携版在 `.tmp\pg`，端口 **55432**，trust 认证 | 机器重启后必须重跑 `.tmp\pg\start-pg.ps1`；没有 Docker，不要用 `docker compose` |
| 开发库 | `easycrm`（种子数据） | `easycrm_test` 由 pytest 建/删，验收不要动它 |
| 后端 | **P2 用 8081**（或重启 8080） | **8080 上现在跑的是 P1 旧实例**：它没有 `/api/v1/opportunities`，对机会请求返回 **404**。看到 404 先查端口，不是 P2 的缺陷 |
| 端口 8000 | 本机被系统禁用 | 绑定必失败（`WinError 10013`），不要用 8000 |
| 前端 | `localhost:5173`（Vite） | 代理目标默认仍是 8000；本机必须用 `VITE_API_PROXY` 覆盖（P2 指向 8081） |

**判别当前连的是 P1 还是 P2 实例**（10 秒）：

```powershell
# 未登录访问机会接口：P2 返回 401，P1 旧实例返回 404
Invoke-WebRequest -Uri http://127.0.0.1:8081/api/v1/opportunities -SkipHttpErrorCheck |
  Select-Object -ExpandProperty StatusCode
```

预期 `401`。若是 `404`，说明这个端口上是 P1 旧实例，换端口或重启该端口的后端。
